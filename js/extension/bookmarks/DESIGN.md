# 书签插件视觉与交互设计规范

## 界面术语

本规范固定使用：搜索框、搜索下拉、tag按钮、功能按钮、书签部分、书签搜索结果、整理模式。各名称的唯一定义见 `REQUIREMENTS.md`“界面术语”；不得把搜索下拉、引擎菜单和书签搜索结果混称为“搜索结果”。

## 1. 设计结论

浏览态应当像用户长期使用的 Pages 单页面，而不是重新设计成后台管理器。

一句话标准：

> 白底、居中搜索、结构性留白、目录瀑布流、目录内宽松纵向书签行，管理能力退到第二层。

交互视觉只保留三层：

| 层级 | 适用对象 | 边界表达 | 交互结果 |
| --- | --- | --- | --- |
| 固定结构 | 目录、搜索框、表单字段、整理工具条 | 单层边框，无阴影 | 保持在页面平面 |
| 普通浮层 | tag、工具、搜索、引擎、Select、Combobox | 无外描边，统一激活阴影 | 点击 / Enter 立即执行并关闭 |
| 模态 | 编辑、确认、设置、导入导出 | 遮罩 + 单一表面 + 模态阴影 | 完成必要输入或确认后关闭 |

边框表示固定范围，阴影表示正在交互，背景变化表示当前目标，间距表示内容结构。顶部搜索带因下方内容独立滚动，允许用克制阴影表达覆盖关系。不得用边框、padding、背景和内层卡片重复表达同一层级。

## 4. 页面与搜索区域

### D-001 页面背景

- 浏览态主背景为白色。
- 不使用大面积浅灰后台底色。
- 不使用渐变、玻璃拟态、品牌色铺底或装饰图形。
- 留白来自内容边距和搜索区域，不来自放大卡片间距。
- 主内容占据搜索带以下的剩余视口并独立滚动；使用不参与内容宽度计算的覆盖式 ScrollArea，细滑块覆盖在最右侧且只在悬浮或滚动交互时显现，左右内容边距不得因滚动条失衡。
- 页面服务于已熟悉功能的单一用户，不放置可见教学说明、功能提示语或重复状态符号；不可见无障碍文本不受此限制。

### D-002 搜索带

Pages 参考值：顶部约 `2rem`、底部约 `1rem` 内边距，搜索带下方留出约 `2rem` 呼吸区。

- 搜索组合整体水平居中，结构是“独立引擎入口 + 独立搜索框”，不把两者包进同一个大胶囊。
- 普通字符支持全页面直接输入：当焦点不在其他编辑控件或模态内时，首个字符即转入搜索框，不需要先点击或按 `Ctrl/Cmd+K`；带修饰键的系统 / 应用快捷键不被截获。
- 搜索框桌面宽度约 `30rem`，高度约 `3rem`，字体约 `1.2rem`，胶囊形细灰边框。
- 搜索引擎位于输入框左侧，只显示约 `1.1rem` 的浏览器缓存图标 + 当前名称；不额外插入搜索图标、分隔栏或下拉箭头。搜索框不显示功能教学型 placeholder。
- 不在同一行常驻浏览/整理 tabs、Logo、说明和多枚主按钮。
- 默认焦点清晰但克制，边框轻微加深即可。
- 搜索带固定在独立滚动内容上方，使用克制的单向下投影消除滚动后顶部空白感，不再使用底部细线；阴影不得扩散成后台式厚重顶栏。

### D-003 搜索浮层

- 与输入框左边和宽度严格对齐。
- 引擎名称改变会移动搜索框；搜索下拉在引擎切换、查询变化和重新显示后的下一次 DOM 布局完成时重新测量搜索框，不得复用初次挂载坐标。
- 桌面宽度约 `30rem`。
- 只有 `#` tag 和 `!` 快捷搜索使用白底、`7px` 圆角和统一激活阴影，外层无描边；普通文本搜索不渲染浮层。
- 浮层只有一层内容表面；删除教学说明、灰色标题底、内层边框和多余分割线。
- hover、键盘 active 使用同一浅灰背景，selected 使用稍深的中性灰绿背景；精确 tag 不再增加左侧色条或 inset 阴影。
- hover 与 active 必须可区分：hover 使用浅灰，active 使用 selected 背景；鼠标进入结果时同步 active 索引，使后续方向键从鼠标所在项继续。
- 长列表隐藏会占宽的原生滚动槽，滚轮和触控滚动保持可用；结果文字宽度不因是否出现滚动而变化。
- 结果行以标题和次级 URL 为主，不做卡片套卡片。
- 高亮使用中性浅灰；主色只能作为焦点细节。
- 内容多时内部滚动，不撑破视口。
- 引擎入口默认无边框、无阴影和下拉箭头；悬浮直接打开列表，横移使用短延迟避免闪退。菜单沿用搜索浮层的无描边表面和激活阴影，当前项使用 selected 背景和勾选，不显示“内置”等说明。
- 引擎切换使用受控 Popover 承担定位和外部关闭，列表项是点击即执行的命令；不把标准 Select 的点击开关生命周期强行改造成 hover。表单目录选择继续使用 Select。
- 引擎 Popover 打开时主搜索浮层不渲染；两者共享顶部空间但绝不同时出现。
- `!` 快捷浮层只渲染 `search_site` 站点目标，不显示带 `search` 的普通搜索引擎；当前引擎入口继续显示，用于明确站点搜索的实际执行引擎。
- 引擎 selected 使用 `--surface-selected`，鼠标 / 键盘 active 使用更明确的 `--surface-active`；搜索结果 active 使用同一变量，纯 hover 使用 `--surface-hover`。不得用同一个背景值混淆三种状态。
- 自定义引擎覆盖同名或同服务域名的内置项后，菜单只显示自定义项。

候选浮层有三种互斥内容状态：

- 叹号目标：只显示 `search_site` 站点目标及 `site:<domain>`；筛选词和真正搜索关键词在视觉上可区分，但不增加第二个输入框。
- tag 候选：输入 `#` 后显示匹配的 tag 名称、书签数量和搜索能力标记；候选高亮与键盘选择规则和普通结果一致。
- 空状态：一句紧凑说明和可选的“配置搜索目标”次级入口，不出现大面积插画或功能教学。

普通文本只改变主目录区的过滤结果；按 Enter 直接执行当前引擎搜索，不维护隐藏的书签候选 active 状态。

`search`、`search_site` 不作为普通内容标签展示。

### D-004 左侧 tag 面板

- 只有存在真实 tag 时才显示入口；入口位于内容区左缘，与右下主工具入口统一为 36px 命中区、15px 图形和弱中性底板，默认无边框、无阴影，不显示 tooltip、文字 Logo、说明或彩色导航点阵。
- 悬浮入口后在其右侧展开约 `240px` 的悬浮面板；入口与面板之间使用约 140ms 关闭缓冲，鼠标横移不会闪退。点击和键盘聚焦仍可打开；面板覆盖内容边缘但不改变瀑布容器宽度，因此不触发 Macy 重排和目录跳动。
- 面板使用白底、`7px` 圆角和统一激活阴影，外层无描边；删除“标签”标题栏、关闭按钮和分割线，只保留带单层边框的紧凑过滤输入及 tag 列表。
- tag 行是单选命令项，不使用复选框或独立 token；hover、键盘焦点和与当前 `#tag` 完全同名的项具有一致的中性高亮。
- 点击 tag 后悬浮面板立即关闭，搜索框内容变为 `#tag`，主搜索浮层也保持关闭，焦点回到搜索输入框。
- 面板只改搜索框文本，不直接改主内容过滤状态；精确匹配由同一个查询解析器得出，使鼠标与键盘始终共享同一状态机。
- 点击面板外、再次点击入口或按 Esc 关闭；关闭动画短且克制，不保留遮挡点击的透明层。
- 窄屏沿用相同悬浮逻辑，但面板宽度受 `calc(100vw - 2rem)` 限制，不能覆盖关闭入口或造成横向滚动。

## 5. 目录瀑布流

### D-010 容器

Pages 参考值：内容左右边距为视口的 `5%`，窄屏降为固定小边距。

- 桌面使用 Macy 类真实瀑布布局。
- 约 1920px 视口呈现 4 列；中等桌面按宽度降为 3 列或 2 列。
- 浏览器顺序仍是数据与整理写回顺序；浏览态 Macy 使用最短列优先重排，不启用 `trueOrder`，避免高度不均时某些列明显溢出。
- 搜索、折叠、数据同步和 favicon 完成后不产生重叠。

### D-011 目录块

Pages 参考值：宽约 `25rem`、细灰边框、约 `1rem` 圆角、块间距约 `1rem`。

- 目录块本身是信息容器，不再给内部每个书签加独立卡片边框。
- 目录头浅灰底、标题居中、细底边；标题使用约 `1.1rem` 常规字重。
- 目录头固定为接近 Pages 自然尺寸的 `36px`，标题通过 flex 垂直居中，不拉高到书签行高度；展开列表与折叠 `...` 行都从标题下方 `10px` 处开始。目录上下边框共 `2px`，所以“边框 + 目录头 + 内容前距”严格等于 `48px`；普通书签与折叠占位也为 `48px`，目录总高度为 `(n + 1) × 48px`。目录块间距使用半行 `24px`，使不同列边框只出现 `0 / 24px` 两种相位。
- 浏览态默认只显示目录名称。
- 浏览态目录头不显示折叠箭头；数量、目录图标和管理按钮不得挤占标题行，确有需要时只在整理态呈现。

## 6. 书签行

### D-020 尺寸与排版

Pages 参考值：每行约 `3rem` 高，内容区比目录块左右各缩进约 `2rem`。

- 每个书签行固定约 `3rem` 高、宽度为目录宽度减约 `4rem`，水平居中。
- favicon：约 `1rem`，无底板、无边框，与标题同处第一行。
- 标题：约 `1rem`、常规字重、单行省略，与 favicon 间距约 `0.38rem`。
- 标题使用固定 `1.4rem` 行盒并留足字形上下空间；hover 在该行盒内把字号从 `1rem` 过渡到约 `1.05rem`，浏览器逐帧重新排印以保持清晰，不使用 `transform: scale()`，不裁字、不挤压 URL、不改变 `3rem` 行高。
- URL：位于第二行但从整个书签行左缘开始，不跟随标题缩进；约 `0.62rem`，灰色，单行省略。
- 行间不使用当前反例中的密集横向分割线。
- 没有标签和备注时不保留空白槽位。
- 有标签时默认不应改变所有行高；可在 hover、编辑或筛选入口中使用。

### D-021 hover 与焦点

- hover 时标题只在固定行盒内做轻微字号或颜色变化，不使用会造成中间帧模糊的纹理缩放，不抬升整张卡片。
- favicon 整体在书签行 hover 时以约 3 秒线性周期旋转，真实缓存图和本地占位均保持同样反馈，这是 Pages 已有行为。
- favicon 加载状态可以有轻量 spinner，但不能替代 hover 旋转。
- 键盘焦点应可见，且不能造成布局位移。
- 有备注时 hover 和键盘焦点可访问备注提示。

## 7. favicon 设计

### D-030 来源与加载

- Chrome / Edge 首选浏览器扩展原生 `/_favicon`，读取浏览器已有缓存。
- 含 `#` 的 SPA 书签先查询精确书签 URL，再尝试移除 fragment 的页面 URL 和站点根地址；同一候选只生成一次。精确 URL 必须在首位，避免 Chrome 为未命中的规范化地址返回默认图后阻断真实缓存候选。
- 同一 URL / 域名复用结果，避免重复加载。
- 初始化不能对全部书签逐个访问网站或公共 favicon 服务。
- 原生缓存图片覆盖在常驻的本地默认图标上；加载中、缓存缺失或来源失败时直接露出本地占位，不出现空白或破图，网络降级必须单独控制。
- 页面启动时即生成 favicon 读取版本，普通页面刷新也不会退回历史默认图。右下工具区使用 `RefreshCw` 图标提供全量刷新，不显示常驻说明文字；点击后按钮短暂旋转，并为全部原生 `/_favicon` 请求切换到新的统一版本号。该操作只重读当前 profile 缓存，不打开或请求各书签站点。
- 图片加载完成前保持 16px 稳定占位，不能让文字左右跳动。
- 图标失败不显示破图标记。
- WXT 开发浏览器使用独立 profile，不能读取日常 Chrome 的 favicon 数据库；本地开发 profile 必须持久化并以绝对路径传给 Chrome，访问过的站点图标才能跨重启保留。没有缓存时保持本地占位，不得误判为网络加载故障。

### D-031 刷新

- 手动刷新只在整理态或低频菜单中出现。
- 刷新按钮与 favicon 显示忙碌反馈。
- 刷新单项不能让其他行图标闪烁或整个瀑布重建。

## 8. 管理能力的视觉位置

### D-040 浏览态工具

新增、目录、整理、全部展开、全部收缩、刷新图标和设置都属于次级工具。

- 工具入口与 tag 入口组成左侧短工具轨道：tag 在上，`Menu` 在下；无真实 tag 时 `Menu` 占据首位。图形统一为 15px，按钮及默认占位均为 36px。入口使用相同弱中性底板，无边框和阴影；鼠标悬浮或键盘焦点进入后，工具组形成白色、`7px` 圆角的统一阴影表面并向下展开，单个操作项不各自描边或投影，离开后收回。
- 工具项 hover / active 沿用普通浮层状态；点击命令立即执行，直接动作同时收起工具组，需要输入的动作直接打开对应模态。
- 主入口本身点击也可展开工具组，避免 Esc 收起后指针未重新进入时入口失效；点击不是第二套页面状态，只是悬浮入口的兼容触发。
- 全页面移除浏览器原生 focus outline；保留组件自行设计的输入边框变化、选中背景和状态反馈。
- 展开项使用带不可见无障碍名称的紧凑图标按钮；不使用常驻文字或额外教学说明增加噪声。
- 不能使用固定左侧栏。
- 不能让蓝色大按钮成为首屏最强视觉元素。
- 全部展开使用 `Maximize2`，全部收缩使用 `Minimize2`；不再使用难以区分的上下双箭头，二者不占独立导航条，也不在目录标题旁重复出现。

### D-041 整理态

- 整理态是同一页面的工作状态，不切换成后台式新页面；搜索带、内容宽度、字体、颜色和目录结构继续沿用浏览态。
- 整理工具条属于固定模式结构，只使用工具条自身的一层边界且不使用浮层阴影；内部不再给分段控件套第二层边框，目录 / 书签只用 selected 背景表达当前状态。
- 进入后出现一条按内容收缩的连续紧凑工具条：目录 / 书签分段控制、整体展开 / 收缩、新增和撤销使用一致间距，不用弹性空白把命令推向两端。桌面保留目录 / 书签文字，仅极窄屏退化为图标；窄屏可用宽度从左侧轨道右边开始计算，不能与 tag按钮重叠。不存在需要额外确认的“完成”按钮；Esc 在没有更高交互层时退出整理态。工具条不能盖住搜索框、贴住目录边框或另起品牌顶栏。
- 进入时以当前视口中的目录或书签作为滚动锚点；布局切换后将锚点恢复到接近原位置，避免跳回顶部。
- 顶部搜索和左侧 tag 在整理态继续工作，直接过滤整理画布；普通文本和 `#tag` 与浏览态共用解析器，不显示“整理时显示全部”等与实际行为冲突的提示。
- 查询非空时拖拽把手和 Sortable 继续可用。放下后读取拖动项相邻的前后可见节点，以它们在完整数据中的真实索引计算落点；不可见节点不参与界面命中，但保持原相对顺序。
- 书签子模式保留全部目录容器作为跨目录投放目标，非匹配目录显示为空投放区；目录子模式才过滤目录容器。没有前后可见锚点的目标目录按尾部追加处理。
- 书签整理画布继续使用 Macy，并启用 `trueOrder` 保持浏览器书签 DOM 顺序；目录高度由标题、当前折叠状态和实际书签数量自然决定。目录整理已经强制等高，不使用 Macy 的绝对定位，切换为同断点、24px 间距的正常流 CSS Grid。
- 书签整理中的临时收缩平时只显示标题行，不渲染浏览态的 `...`，也不常驻空投放区。其书签容器以零高度保留 Sortable 命中能力；拖动书签靠近标题下方时，仅当前目标目录动态展开一行高投放区并触发 Macy 重排，离开后收回，放下后目标目录在整理态自动展开以显示结果。目录整理不使用这套动态投放逻辑。每次单目录或整体展开 / 收缩仍须重新测高排位。

目录整理：

- 进入目录整理时临时默认全部收缩，使所有目录成为统一高度的 Grid 单元；收缩目录只渲染标题行，不渲染 `...` 或其他空内容。工具条的整体展开 / 收缩始终保留，目录标题也可单独切换。书签整理每次进入时临时默认全部展开；两种整理状态共享独立于浏览偏好的临时折叠集合，返回浏览态时恢复用户原偏好。
- 不显示书签拖拽把手、书签编辑和删除按钮。
- 被拖动目录使用挂到 `body` 的浮动副本跟随指针，脱离 Grid；Grid 内原元素变为唯一的等高虚线预测占位槽，并随 Sortable 预测索引移动。其他目录由正常流 Grid 自动补位，松手后的顺序必须与占位位置一致。
- 预测槽产生的可见目录相对顺序是唯一写回依据；写回时以前后目录保留的 Chrome 绝对 `index` 作为锚点，不能把可见相对下标直接当成根节点绝对下标。写回后重新读取浏览器书签树，使真实顺序与预测槽一致。
- 切换子模式或退出时不擅自覆盖用户刚完成的折叠调整；回到浏览态后以 `trueOrder: false` 重建 Macy。

书签整理：

- 目录保持完整容器，目录头不作为拖拽源；每行只增加一个稳定宽度的拖拽把手和一组 hover / focus 操作。
- 即使浏览态执行过全部收缩，进入书签整理后仍临时显示全部书签行和 Sortable 投放容器，不能出现无可拖动内容的死状态。
- 书签拖拽使用挂到 `body` 的 fallback 浮动副本，避免原生 HTML5 拖拽吞掉鼠标滚轮；Sortable 的滚动容器明确指向页面 ScrollArea，拖动期间滚轮和边缘自动滚动都必须有效。
- 行操作只保留编辑和删除，不提供与结构整理无关的复制 URL。
- 拖动项降低不透明度但文字仍可辨认，原位置保持等高占位，插入位置使用贯穿内容宽度的细线。
- 跨目录时只高亮实际接收目录，空目录也必须具有稳定的可放置高度；无效区域使用 `not-allowed` 光标和克制的错误色边框。
- 靠近可滚动区域上下边缘时平滑自动滚动，速度随距离递增，但不得突然跳屏。

写回与退出：

- 放下后被移动项和相关目录显示局部忙碌状态，其他目录仍可浏览；同一对象的重复动作暂时禁用。
- 成功后插入线消失并短暂显示局部成功状态；失败后动画回到原位置，恢复数据和 DOM，并在原操作附近提示原因。
- 撤销可通过工具条图标和 `Ctrl/Cmd+Z` 触发；即将撤销的对象写入不可见无障碍名称，不增加可见说明文案。
- `Esc` 优先关闭菜单 / 弹窗或取消当前拖拽；没有局部浮层时才退出整理态。存在写回中的操作时，等待结果后再退出，不能静默丢弃状态。
- Esc 每次只处理最高一层：弹窗关闭后仍留在整理态，候选关闭后查询仍保留，查询清空后仍留在整理态，下一次才退出。
- 退出后所有管理控件退场，保留当前搜索、tag 和折叠结果，恢复滚动锚点与 Pages 式浏览布局。

### D-042 弹窗与 Popup

- Dialog 使用遮罩、白色单一表面、`8px` 圆角和统一模态阴影，外层无描边。
- 标题区、正文和 footer 不使用独立背景或分割线；内容通过自然间距分组，不再套卡片。只有输入字段、固定选择范围和必要危险状态使用边框。
- 普通菜单不是缩小版 Dialog：Select、Combobox、搜索和引擎菜单统一使用 D-003 的无描边普通浮层与激活阴影。
- 卡片圆角不超过 8px，除非是 Pages 原有目录块。
- 危险操作以文字、图标和局部状态表达，不使用大面积警示装饰。
- Popup 是窄幅操作面，不照搬主页瀑布布局。
- 编辑模式使用成熟组件库的 Dialog、Form 控件、Select、Combobox 和 TagsInput，不继续维护手写 backdrop、焦点圈、目录下拉和 tag 建议列表。
- 组件采用无样式或可完全覆盖主题的模式，仅复用交互、无障碍和定位能力；最终外观仍使用 Pages 的白底、细边框、紧凑间距，不能变成组件库后台表单。
- Dialog 内容高于遮罩；Dialog 内通过 Portal 渲染的 Select / Combobox 菜单必须再高于 Dialog 内容。不得依赖 DOM 顺序碰巧覆盖，也不得让菜单出现在半透明遮罩或弹窗下面。
- 导入导出正文直接排列两个操作行，删除分组外框、灰色标题底、行分割线和教学型 intro；危险或不可逆信息仍在执行前明确表达。
- `Esc` 在窗口捕获阶段统一恢复默认浏览态，避免焦点位于 Portal、输入框或拖拽工具时行为分叉；正在写入的导入流程仍不可被中断。

### D-043 tag 输入控件

- tag 字段是一个多行自适应的单体输入容器：token 和输入光标共享同一个外框、焦点状态与换行流；最小高度与普通输入框一致，token 增多时向下换行，不横向撑破弹窗。
- 不允许把 token 列表和 Combobox 输入渲染成上下两个带边界的区域；建议浮层以整个单体字段为定位和宽度基准。
- 已选 token 使用中性浅灰底、细边框和小型移除图标；`search`、`search_site` 使用“搜索能力”文字标识，而不是强烈警示色。
- 建议浮层与输入容器同宽，最大高度受视口限制；每项显示 tag 名称和使用次数，已选项显示勾选但不可重复添加。
- 建议分为“已有标签”和“搜索能力”两组；没有完全匹配时，“创建新标签”作为最后一项，避免误触。
- 选择 `search` 后在 tag 字段下方就地展开搜索模板输入和占位符校验；选择 `search_site` 后只显示解析出的目标域名预览。
- 校验错误显示在对应字段下方，不使用全局 toast 代替表单错误；保存失败后保留所有输入和焦点上下文。

## 9. 字体与颜色

### D-050 字体

首选：

```css
"等距更纱黑体 SC", "Sarasa Mono SC", "mononoki regular", "Consolas", monospace
```

所有主页文本统一使用该顺序，不能把英文族名移到本地已安装的中文族名前面，否则会在部分 Windows 环境回退到不同字形。

### D-051 色彩

- 页面：`#ffffff`。
- 目录头：约 `#f5f5f5`。
- 主文字：接近 `#111111`。
- 次级 URL：灰色。
- 边框：接近 `#cdcdcd`，使用细线。
- hover：中性灰或极弱强调色。
- 主色只用于焦点和命令确认，不主导页面。

## 10. 响应式

- 大桌面优先忠实还原 Pages。
- 目录列数随可用宽度降低，最窄为单列。
- 小屏搜索框可缩短，但仍保持搜索优先。
- 工具按钮不得与搜索框重叠。
- 页面不得横向滚动。
- 文本必须在容器内省略或换行，不得遮挡相邻元素。

## 11. 视觉阻断项

出现任一项即不得判定设计通过：

- 浏览态存在固定侧栏。
- 浏览态出现 Logo / 产品说明。
- 浏览态主要结构是后台式固定顶栏。
- 目录占整行，内部书签横向排卡。
- 目录标题左对齐并被图标、计数、箭头和操作按钮包围。
- 每个书签都有明显边框和密集分割线。
- favicon 默认是统一灰色图标而非浏览器缓存图片。
- hover favicon 不旋转。
- 无 extra 的导入数据出现伪造标签或快捷搜索配置。
- 自动化小夹具好看，但真实 214 条数据与 Image #1 的整体气质明显不同。

## 12. 视觉验收方法

至少保存并人工对照：

- 真实 214 条书签，约 1858x1005 视口，和 Image #1 并排比较。
- 搜索框聚焦状态。
- 普通文本过滤且无浮层；`#` / `!` 候选浮层。
- `!` 快捷搜索在有目标和无目标数据下的状态。
- 单目录展开与收缩状态；工具组悬浮展开、全部展开和全部收缩状态。
- favicon 已加载、加载失败、hover 旋转和手动刷新。
- 整理态桌面截图。
- 390px 窄屏截图。

最终视觉通过必须包含用户真实数据确认，不能只依赖 Playwright 断言。
