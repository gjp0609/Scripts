# 交互状态与流程规范

本文档定义用户操作如何经过状态机产生结果。任何实现必须先满足本文件，再选择 Vue、组件库或布局库的具体写法。

## 1. 顶层状态

```text
浏览模式
├─ 普通查询
├─ # tag 查询
├─ ! 快捷查询
├─ 引擎菜单
├─ tag面板
├─ 功能菜单
└─ 模态

整理模式
├─ 整理模式-书签
└─ 整理模式-目录
```

- 顶层模式只有 `浏览模式` 和 `整理模式`。
- 搜索、引擎、tag、功能和模态是浏览模式或整理模式上的交互层，不得改变数据模式。
- 整理模式必须明确当前子模式；两个子模式不能同时挂载拖拽实例。
- 每个状态只有一个拥有者；组件通过事件提交意图，不能互相直接修改对方内部状态。

## 2. Esc 回退顺序

每次 `Esc` 只处理最高层，不跨层清空：

1. 取消当前拖拽，不写回。
2. 关闭 Select、Combobox 或 tag 建议菜单。
3. 关闭书签/目录编辑模态、删除确认或导入导出模态。
4. 关闭引擎菜单、tag面板或功能菜单。
5. 关闭搜索下拉，保留查询文本。
6. 清空查询，恢复完整书签部分，保持当前顶层模式。
7. 整理模式退出到浏览模式，恢复浏览布局和滚动锚点。
8. 浏览模式无其他状态时只把焦点还给搜索框。

正在导入、写回或撤销时不得静默中断；应等待结果或提供明确的不可中断状态。

Esc 只能由页面交互协调器拥有一个窗口级监听器；Dialog、Select、Combobox 等子组件不得各自注册会与页面竞争的全局监听器。子组件只能报告内部菜单已关闭或请求关闭模态。

## 3. 搜索状态机

```text
空输入 ──普通字符──> 普通查询
普通查询 ──输入 #──> # tag 查询
普通查询 ──输入 !/！──> ! 快捷查询
# tag 查询 ──选择 tag──> 精确 # 查询
任意查询 ──Esc──> 上一层 / 清空
```

### 3.1 普通查询

- 只过滤书签部分。
- 不创建搜索下拉，也不维护隐藏书签 active 项。
- `Enter` 执行当前引擎。
- 上下键切换引擎；切换后 selected 立即更新。

在整理模式-目录中，普通查询只匹配目录标题；在整理模式-书签中，普通查询匹配书签字段但不移除目录投放容器。

### 3.2 `#` 查询

- 输入变化同时更新候选和书签部分预览。
- 候选列表有一个 `activeIndex`，鼠标进入候选必须写入同一个索引。
- `ArrowUp/Down` 从当前 active 继续循环。
- `Enter` 等价于点击 active 候选，并写入完整 `#tag`。
- 引擎菜单打开时 `#` 搜索下拉关闭；引擎菜单关闭且查询仍有效时恢复。

### 3.3 `!` 查询

- 只显示 `search_site` 目标。
- `!` 前的目标词和空格后的关键词由解析器一次性产生，不维护重复字段。
- 只有目标有效且关键词非空时 `Enter` 执行。
- 当前普通引擎入口保持可见，用于表达实际执行者。
- `!` 查询不渲染普通书签搜索结果，但保留书签部分背景和当前引擎入口。

## 4. selected、active、hover

- `selected`：已确认并正在使用的对象，例如当前引擎或精确 tag。
- `active`：键盘或鼠标当前将要确认的对象。
- `hover`：指针经过但未必成为 active 的视觉状态；候选列表要求 hover 同步 active，固定内容不强行同步。
- selected 和 active 可同时存在于不同项，不能用一个 `current` 布尔值代替。
- Enter 永远确认 active；没有 active 时使用明确的默认项，不读取 DOM 顺序猜测。
- 点击后立即执行并关闭当前浮层，不能留下“已选但未提交”的第二阶段。

## 5. 浮层互斥

搜索下拉、引擎菜单、tag面板和功能菜单是普通浮层，同一时刻最多一个可见。

- 浮层内容只由状态机决定，不由 CSS 隐藏后继续接收键盘事件。
- 悬浮入口到浮层保留关闭缓冲；点击入口是悬浮触发的兼容路径，不是另一套打开模型。
- 浮层位置以真实锚点 DOM 测量；锚点宽度变化、窗口变化和重新显示都必须重新测量。

## 6. 整理流程

### 6.1 进入与退出

进入整理模式时保存滚动锚点、查询和浏览折叠偏好，创建对应子模式的临时布局状态。退出时销毁拖拽和整理布局实例，恢复浏览模式布局，不重置查询或用户偏好。

### 6.2 书签拖拽

1. 按下稳定拖拽把手。
2. 生成脱离页面滚动层的拖动副本，保留原位置预测槽。
3. 根据指针所在目录和前后可见项计算真实投放目标。
4. 空目录和收缩目录平时已有一行稳定投放几何；命中后目标目录动态展开真实列表，唯一插入线表达最终位置，空目录显示一条插入指示。
5. 放下后以同一预测结果写回浏览器 API。
6. 成功更新视图并记录撤销快照；失败恢复原视图。

拖拽排序不能直接使用过滤数组下标。完整顺序、可见锚点、预测顺序、同父级 API 索引和跨目录尾部追加必须由同一个 `MovePlan` 纯函数链推导；拖拽结束不得重新读取已变化 DOM 再计算另一份结果。

拖动期间页面捕获指针和滚轮：滚轮直接滚动书签部分，指针接近上下边缘时逐帧自动滚动；每次指针或滚动变化都重新命中目录与可见锚点。

### 6.3 目录拖拽

1. 进入整理模式-目录后始终使用只含标题的等高 Grid。
2. 拖动副本脱离 Grid，应用状态持有预测顺序，Grid 中只有源项对应的唯一等高预测槽。
3. 其他目录由正常流 Grid 自动补位。
4. 放下后直接提交同一 `MovePlan`；浏览器绝对 index 基于完整根节点顺序并处理同父级向后移动语义。

目录卡片不再划分前后半区。指针进入目标卡片后，预占位直接占据目标在拖拽开始时的原槽位，目标及中间目录按移动方向顺延；指针位于卡片间隙时保持当前预测。预测槽自身不能再次成为锚点。

## 7. 模态流程

- 添加/编辑：打开表单，保存成功关闭；失败保留输入。
- 删除：打开确认，确认后写回；失败保留确认上下文。
- 导入导出：执行期间锁定不可中断操作；无效文件零修改失败。
- 模态内 Select/Combobox 的 Esc 先关闭自身菜单，再关闭模态。

## 8. 变更评审门槛

每个修复提交前必须提供：

- 受影响状态和不受影响状态。
- 状态转移前后输入、视图和数据结果。
- 组件所有权变化（如有）。
- 浏览模式回归项。
- 至少一个成功、失败和 Esc 路径。

没有这些内容的局部条件、定时器或 DOM 补丁不得合入。
