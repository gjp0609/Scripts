# 书签插件产品需求

本文档只定义产品目标、用户流程和验收结果。交互状态见 `INTERACTION.md`，视觉参数见 `DESIGN.md`，代码边界见 `ARCHITECTURE.md`，验证范围见 `TEST_CHECKLIST.md`。

## 1. 产品定位

这是一个高频、自用、以浏览和搜索为主的浏览器书签页，是 Pages 单页面的升级版，不是管理后台、品牌页或通用书签产品。

升级目标：

- 使用浏览器原生书签作为主数据。
- 保留 Pages 的浏览效率和整体视觉节奏。
- 增加搜索能力、tag、CRUD、拖拽整理、Popup 保存和完整备份。
- 管理能力不能降低日常浏览体验。

事实优先级：

1. 用户最新明确确认。
2. 本文档体系。
3. `R:\Files\Workspace\Mine\pages\docs\single\bookmarks\index.html` 及 `style.css`。
4. 当前代码、历史提交和 `tmp/` 原型只用于分析，不是需求来源。

## 2. 固定术语

| 名称          | 定义                                                       |
| ------------- | ---------------------------------------------------------- |
| 浏览模式      | 页面默认状态，只用于搜索、浏览、打开书签和调用低频工具     |
| 搜索框        | 顶部唯一文本输入，解释普通文本、`#` 和 `!`                 |
| 搜索下拉      | 搜索框下方仅用于 `#` tag 候选或 `!` 站点候选的浮层         |
| 引擎菜单      | 搜索框左侧搜索引擎入口展开的候选列表，不属于搜索下拉       |
| tag按钮       | 左侧工具轨道中打开 tag 面板的入口                          |
| tag面板       | tag按钮展开的鼠标筛选兼容层，不拥有独立筛选状态            |
| 功能按钮      | tag按钮下方打开低频命令组的入口                            |
| 书签部分      | 搜索带下方的目录与书签主体                                 |
| 书签搜索结果  | 普通文本过滤后仍留在书签部分中的目录和书签，不是浮层       |
| 整理模式      | 维护书签结构的工作状态，包含两个互斥子模式                 |
| 整理模式-书签 | 拖动、编辑、删除书签及跨目录移动的子模式                   |
| 整理模式-目录 | 拖动、重命名、删除目录的子模式                             |
| 模态          | 添加、编辑、删除确认、导入导出等需要完成输入或确认的遮罩层 |

后续沟通、代码命名和测试必须使用这些名称，不能把搜索下拉、引擎菜单和书签搜索结果统称为“搜索结果”。

## 3. 全局产品原则

### 3.1 自用且安静

- 不显示 Logo、产品说明、教学文案和功能介绍。
- 搜索框不使用功能教学 placeholder。
- 不显示多余下拉箭头、折叠箭头、完成按钮和重复状态提示。
- 可访问名称保留但不作为可见说明。
- 错误、危险操作和数据写入结果仍须明确，不以“自用”为由隐藏必要反馈。

### 3.2 最短操作路径

- 高频操作应通过直接输入、悬浮发现、点击或 Enter 完成。
- 每个可由键盘完成或退出的界面状态，必须提供等价的鼠标路径；鼠标路径不得依赖精确穿越不可命中的间隙。
- 直接命令执行后立即关闭对应浮层。
- 只有必须填写数据或确认风险时才进入模态。
- 同一结果只能有一个状态来源；不得为鼠标和键盘维护两套业务状态。

### 3.3 修复完整性

任何代码修复必须先回答：

1. 用户要完成的完整任务是什么。
2. 当前处于哪个模式和交互层级。
3. 输入、状态变化、数据写回和视觉结果分别是什么。
4. 会影响哪些相邻流程和不可退化项。
5. 应修正哪个拥有该职责的模块，而不是在哪个调用点追加条件。

禁止以 DOM class、延时器、额外布尔量或重复 watch 掩盖不清晰的状态所有权。临时绕行只有在文档明确标记、具备删除条件且不改变产品契约时才允许。

## 4. 数据契约

### 4.1 主数据

- 浏览器书签 API 是目录、书签、归属和顺序的唯一主数据。
- 插件不得复制整棵书签树到 storage 后作为另一份主数据。
- 首版显示默认书签根下的一层目录及其直属书签；更深层级必须明确降级，不能静默混排。
- 页面打开期间响应浏览器书签的创建、修改、删除、移动和浏览器原生重排事件；`onChildrenReordered` 后必须重新读取真实顺序。
- Chrome 134+ 优先以 `folderType: bookmarks-bar` 识别书签栏；存在账号与本地同类根时优先当前同步根，旧版字段缺失时才使用 ID 和标题兼容识别。

### 4.2 额外数据

普通导入书签没有 tag、备注、搜索模板或 favicon 覆盖，这是正常状态。插件不猜测、不补造。

```ts
type BookmarkExtra = {
    bookmarkId: string;
    tags: string[];
    description?: string;
    searchUrl?: string;
    faviconOverride?: string;
    updatedAt: number;
};
```

- extra 只保存浏览器书签没有的字段。
- 缺少 extra 等价于空 extra，不能阻断显示。
- 删除书签或目录后同步清理关联 extra。
- 删除后的 extra 清理允许有限重试；最终失败必须记录明确错误，并可由手动维护重新清理。
- 扩展申请 `unlimitedStorage` 保存 tag、偏好和备份恢复映射；维护操作仍应清理已失效引用，不能把无限容量当作永久堆积理由。
- 这是新插件，不设计旧版插件数据兼容或迁移。
- v3 导入执行严格 schema 校验；损坏或字段类型错误的 extra 必须拒绝，不能静默补默认时间或丢弃错误字段。

### 4.3 写回一致性

- 所有新增、编辑、删除、移动和排序必须写回浏览器书签。
- 成功后视图与浏览器真实数据一致。
- 失败时恢复视图，保留可理解的局部错误，不生成虚假的撤销记录。
- 导入使用补偿事务：记录原节点和 storage 状态，失败时逐项回滚，重新读取书签栏子树校验；回滚或校验失败必须明确提示用户刷新检查，不能静默吞掉二次失败。
- 编辑书签更换目录时追加到目标目录尾部。

## 5. 浏览模式保护契约

浏览模式是默认主页，也是后续重构的最高优先级回归边界。

### 5.1 结构与视觉

- 白色页面、顶部居中搜索、下方独立滚动的书签部分。
- 目录使用多列瀑布流；目录内部使用纵向书签行。
- 浏览模式 Macy 使用最短列优先，不按 DOM 顺序强制保序排布。
- 搜索框是第一视觉和第一交互入口。
- 页面主体是书签，不常驻侧栏、Logo、模式栏或管理工具栏。
- tag按钮和功能按钮组成左侧短工具轨道；没有 tag 时不显示空 tag按钮。

### 5.2 目录与书签

- 目录标题居中，点击标题切换单目录展开或收缩。
- 目录标题不显示折叠箭头；收缩状态由内容消失和 `...` 表达。
- 目录总高度落在既定 48px 内容网格上，目录间距为 24px，相邻边框只出现 0 或 24px 相位差。
- 书签行固定 48px，favicon 与标题在第一行，完整 URL 从整行左缘开始第二行。
- 标题 hover 不改变行高、不位移、不裁字、不使用造成中间帧模糊的缩放。
- favicon 与本地占位在书签 hover 时均旋转。
- 点击书签在新标签页打开。

### 5.3 折叠与布局

- 单目录和全部展开/收缩都可用，并持久化浏览模式偏好。
- 搜索命中不受持久折叠状态遮挡。
- 折叠、搜索、数据变化和图标加载后不得重叠或产生残留高度。
- 覆盖式滚动条不占内容宽度，左右视觉边距一致。

### 5.4 不可被整理模式污染

- 浏览模式不渲染拖拽把手、编辑、删除或目录计数。
- 整理模式的临时折叠、Grid、trueOrder、投放区和拖拽状态不得写入浏览模式布局状态。
- 退出整理模式后恢复浏览模式布局引擎、视觉结构、折叠偏好、搜索和合理滚动位置。

## 6. 搜索需求

### 6.1 统一输入解释

搜索框只有一个查询值，按以下互斥顺序解释：

1. `!` 或 `！`：快捷站内搜索。
2. `#`：tag 搜索。
3. 其他非空文本：普通过滤与网络搜索。
4. 空文本：完整浏览状态。

页面没有打开其他可编辑字段或模态时，直接输入普通字符应进入搜索框并保留首字符；组合键和输入法组合不得被错误截获。

### 6.2 普通搜索

- 匹配目录名、书签标题、URL、域名，以及存在时的普通 tag 和备注。
- 只过滤书签部分，不显示搜索下拉，不维护隐藏候选索引。
- `Enter` 使用当前引擎搜索完整输入。
- `ArrowUp` / `ArrowDown` 循环切换当前可见搜索引擎。
- `Esc` 按交互层级规则恢复完整书签部分。

### 6.3 搜索引擎

- 无自定义配置时至少提供 Bing；可提供 Google。
- 具有 `search` tag、搜索模板为有效 HTTP(S) URL 且包含 `{keyword}` 的书签成为自定义引擎；编辑、导入和运行时识别必须共用同一校验规则。
- 用户已配置相同名称或相同服务域名的 Bing/Google 时，隐藏对应内置项。
- 引擎菜单区分 selected（当前引擎）与 active（键鼠当前目标）。
- 鼠标进入候选会更新 active；方向键和 Enter 从该位置继续。
- 引擎菜单与搜索下拉互斥，不能同时显示。

### 6.4 `!` 快捷站内搜索

只使用带 `search_site` tag 且 URL 为有效 HTTP(S) 地址的书签作为目标；`search` 引擎不得混入。

| 输入           | 目标筛选 | 关键词 | Enter        |
| -------------- | -------- | ------ | ------------ |
| `!`            | 全部目标 | 空     | 不执行       |
| `!目标`        | 匹配目标 | 空     | 不执行       |
| `! 关键词`     | 全部目标 | 有     | 当前目标执行 |
| `!目标 关键词` | 匹配目标 | 有     | 当前目标执行 |

执行时生成 `site:<domain> <关键词>`，交给当前普通搜索引擎。当前引擎入口在 `!` 模式保持可见，用于明确实际执行引擎。

`!` 模式只改变搜索下拉和执行路径，不隐藏当前引擎入口；书签部分不显示普通文本的书签搜索结果，但保留目录主体作为背景上下文。

### 6.5 `#` tag 搜索

- `#` 显示全部真实 tag；`#xx` 动态匹配前缀和包含项。
- 部分匹配时，书签部分预览所有候选 tag 的并集。
- 与已有 tag 完全匹配时自动进入精确筛选。
- 上下键、鼠标 hover 和 Enter 共享同一个 active 候选。
- 选择后搜索框写成完整 `#tag`，查询文本是唯一筛选来源。
- 无 tag 时显示紧凑空状态，不生成假 tag。

### 6.6 tag面板

- tag面板只是 `#` 搜索的鼠标兼容层。
- 点击 tag 等价于向搜索框输入并选择 `#tag`，随后关闭面板、聚焦搜索框。
- tag面板不直接写入第二套过滤状态。

## 7. 整理模式

### 7.1 共同行为

- 整理模式仍使用同一搜索框和书签数据，不切换成后台页面。
- 普通搜索和 `#` tag 搜索必须可用；`!` 继续保持搜索语义。
- 查询非空时仍允许拖拽，落点按完整数据中的真实相对位置计算；不可见项保持原相对顺序。
- 整体展开和整体收缩始终可用。
- 不提供“完成”和“复制 URL”。
- 整理模式提供立即生效的“退出整理”鼠标命令；它只切回浏览模式，不表示提交或保存批次。
- 弹窗 Esc 只关闭弹窗，不退出整理模式。
- 整理模式-书签中的普通文本按书签字段过滤，目录容器始终保留为投放目标。
- 整理模式-目录中的普通文本只匹配目录标题，不按目录内书签字段过滤目录。

### 7.2 整理模式-书签

- 使用独立的保序 Macy 画布，不复用浏览模式的最短列布局实例。
- 目录作为跨目录投放目标始终存在；搜索只过滤书签内容。
- 支持同目录排序、跨目录移动、编辑和删除。
- 进入该子模式时使用独立临时折叠状态，不覆盖浏览偏好。
- 收缩目录不显示 `...`，但始终保留一行稳定的空白投放区。
- 空目录始终保留同样的一行空白投放区，不显示常驻虚线框或提示文字。
- 拖动开始不得统一改变目录高度；只有命中目标时才显示插入线并按需展开真实列表。
- 拖动书签接近收缩目录时，目标目录按交互需要动态展开真实书签列表和唯一插入线；离开收回，放下后展开并显示结果。
- 拖动期间鼠标滚轮和边缘自动滚动作用于书签部分，并在滚动后持续更新预测落点；滚轮是明确操作，优先于边缘自动滚动，鼠标再次移动后才恢复边缘滚动判定。

### 7.3 整理模式-目录

- 使用正常流等高 Grid，不使用 Macy。
- 目录子模式始终只显示标题，不渲染书签内容，也不提供单目录或整体展开/收缩。
- 拖动副本脱离 Grid；原位置由唯一等高预测槽表示。
- 预测槽的位置必须与最终浏览器写回位置一致。
- 根目录中夹有直属书签时，仍按浏览器绝对索引正确写回。
- 不显示书签拖拽、编辑或删除操作。

整理模式-目录的 `#` 查询仍按 tag 匹配目录内书签并保留所属目录；普通文本则只按目录标题匹配。

### 7.4 写回失败

- 整理模式不提供撤销按钮，也不接管 `Ctrl/Cmd+Z`；编辑字段继续使用浏览器原生撤销。
- 写回失败时重新读取真实浏览器数据，并恢复布局和临时折叠状态。
- 失败操作不得留下可再次执行的移动快照或其他隐式状态。

## 8. 编辑、删除和备份

- 添加/编辑书签支持标题、URL、目录、tag、备注和搜索模板。
- tag 输入使用成熟的 TagsInput + Combobox 行为：已有 tag 补全、新建 tag、去重、粘贴拆分和输入法安全。
- `search` 与 `search_site` 互斥；前者要求包含 `{keyword}` 的有效 HTTP(S) 搜索模板，后者要求有效 HTTP(S) URL。
- 当前页面必须监听工作区相关的 `storage.local` 变化；其他扩展页面修改 tag、备注、搜索模板或偏好后即时更新当前视图。已有 extra 的书签从非展示层级移回当前目录时必须重新读取 extra，不得临时退化为空数据。
- 目录选择和 tag 菜单必须正确定位在模态之上。
- 删除书签和目录必须确认，失败不得假装成功。
- 完整 JSON 备份从浏览器书签栏完整子树生成，递归包含根直属书签、嵌套目录、嵌套书签、extra 和必要偏好；不能只导出当前单层展示投影。
- JSON 使用 v3 递归节点并保存导出实例 `originId` 和导出时的 `sourceId`。同一实例导入优先按 `sourceId` 找回被移动的原节点；跨实例首次导入按目标父目录内的节点类型、标题、URL 和原顺序匹配，重复内容按出现顺序配对，避免 ID 碰撞导致 extra 错配。每个 `originId + sourceId -> targetId` 映射必须持久化，原节点被 Chrome 重新创建后重复导入仍复用同一目标节点；extra 只更新本次备份涉及的书签，不能覆盖其他页面刚写入的无关 extra。
- 设置中的“校验并清理”扫描完整浏览器树，只修复扩展数据：规范 tag、删除不存在书签对应的 extra 和恢复映射、清理无效折叠目录与搜索引擎引用；不得调用 `bookmarks.remove` 或 `removeTree`。
- Chrome 不保证恢复时沿用源 ID；`auto` 与 `builtin:*` 内置引擎 ID 保持原值，`bookmark:<sourceId>` 自定义引擎必须恢复为 `bookmark:<targetId>`。无效文件在任何浏览器写入前完整失败。

## 9. favicon

- 优先使用当前浏览器 profile 已缓存的 `/_favicon` 图片。
- SPA 候选顺序为精确 URL、移除 fragment 的 URL、站点根地址。
- 初始化和“刷新全部图标”都不得逐站联网访问书签 URL。
- 页面启动使用新的读取版本，避免刷新后重新显示旧默认图。
- 全部候选失败时显示稳定本地占位，不显示破图。
- WXT 开发浏览器使用独立持久 profile；未访问站点时没有日常浏览器缓存是正常状态。

## 10. Popup

- 打开主页面。
- 读取当前标签页标题和 URL。
- 选择目标目录并保存，成功后关闭。
- 失败时保留表单和错误。
- 没有 bookmarklet 配置时不显示空入口。

## 11. 完成标准

- 浏览模式保护契约全部通过且由用户真实数据确认。
- 三种画布互相隔离：浏览模式、整理模式-书签、整理模式-目录。
