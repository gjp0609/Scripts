本文档是 `js/extension/bookmarks` 的产品需求基线。视觉细节见 `DESIGN.md`，当前状态见 `PROGRESS.md`，验收步骤见 `TEST_CHECKLIST.md`。

## 界面术语

后续需求、实现记录和测试统一使用以下名称，不用“结果”“入口”“浮层”等模糊词替代：

| 名称 | 唯一定义 |
| --- | --- |
| 搜索框 | 顶部用于输入普通文本、`#` 和 `!` 的文本输入框 |
| 搜索下拉 | 搜索框正下方，仅显示 `#` tag 候选或 `!` 站点候选的面板 |
| tag按钮 | 页面左侧打开 tag 列表的标签图标按钮 |

| 整理模式 | 在同一页面显示拖拽、编辑、删除和整理工具条的工作状态 |

## 2. 产品定位

### R-001 核心目标

这是一个高频、自用、以浏览和搜索为主的浏览器书签页。

首要任务：

- 打开页面后立即搜索。
- 快速扫描多个目录。
- 快速打开书签。
- 在不破坏浏览体验的前提下维护浏览器书签。

产品应当是 Pages 单页面的升级版，不是后台管理系统、品牌展示页或组件库仪表盘。

### R-002 升级而不退化

升级内容包括：

- 静态 JSON 改为浏览器原生书签数据。
- 支持新增、编辑、删除、排序和跨目录移动。
- 支持 popup 保存当前页。
- 支持额外数据、完整备份和错误反馈。
- 修复 Pages 的响应式、无障碍和数据维护问题。

升级不能改变以下核心感受：

- 搜索框是页面第一视觉和第一交互入口。
- 浏览态是白底、克制、有结构性留白的书签页。
- 目录块采用多列瀑布流，目录内部是纵向书签行。
- 页面主体是目录和书签，不是侧栏、Logo、模式栏和管理按钮。

### R-003 自用界面原则

这是用户本人长期使用的工具，不是面向陌生用户的产品演示或教学页面：

- 不显示 Logo、用途说明、功能介绍、操作教学和“你可以……”式提示文案。
- 搜索框不使用可见 placeholder 解释 `!`、`#` 或其他功能；搜索能力由用户记忆和键盘操作承载。
- 已能通过点击区域和当前内容理解的控件，不再添加重复的下拉箭头、折叠箭头、状态图标或文字标签。
- 可访问名称、ARIA 和焦点语义必须保留，但应对视觉界面不可见，不以“易发现性”为由增加常驻噪声。
- 全页面隐藏 Chrome 等浏览器自动绘制的原生焦点 `outline`；组件自行设计的输入边框变化、选中背景和必要状态反馈保留，不把二者混为一类。
- 错误、危险操作和数据状态仍须明确反馈；“自用”只删除冗余教学，不删除必要结果与风险信息。

### R-004 最短操作路径与表面语义

页面优先用最少操作完成目标。视觉状态必须直接对应操作阶段，不用层层容器制造层级：

- 固定内容用单层边框确定范围，不使用阴影；包括目录、搜索输入、表单字段和固定整理工具条。
- tag 与工具等独立悬浮入口默认使用一致的弱中性底板，避免在白底上只剩悬空图形；仍不使用边框和默认阴影。引擎入口与搜索组合排版，可保持透明。
- 普通浮层只使用统一白色表面和激活阴影，不再叠加外描边、灰色标题背景、内层卡片或多重分割线。
- hover 与键盘当前项使用同一种浅色背景，selected 使用稍深的中性背景；不再用额外色条、双重边框或独立阴影表达选中。
- 点击或 `Enter` 表示确认当前目标、立即执行并结束本次交互；能从页面结果直接确认成功的动作不增加提示或二次确认。
- 只有添加 / 编辑表单、危险删除、文件导入和多字段设置允许进入模态；模态采用遮罩、单一白色表面和模态阴影，内部主要用间距组织结构。
- tag、右下工具、搜索结果和引擎选择必须共享“悬浮激活 -> 移动到目标 -> 点击确认”的操作节奏。

## 3. 数据模型与缺省行为

### R-010 浏览器书签是主数据

浏览器书签 API 提供：

- 目录名称、层级和顺序。
- 书签标题、URL、目录归属和顺序。
- 创建、修改、删除和移动事件。

所有书签写操作必须写回浏览器书签。插件不得复制整棵书签树到 storage 后作为主数据。

首版只支持默认书签位置下的一层目录及其直属书签。更深层目录必须有明确降级，不得静默混排。

### R-011 导入书签没有额外数据

从浏览器或普通书签文件导入的书签，通常只有目录、标题和 URL。以下字段默认不存在：

- 标签。
- 备注。
- `searchUrl`。
- favicon 覆盖。
- 插件 UI 偏好。

这是正常数据状态，不是加载失败。

界面规则：

- 不伪造标签、备注或 `searchUrl`。
- 不从目录名、标题或域名猜测额外数据。
- 没有标签时不展示空的标签侧栏或占位区。
- 没有快捷搜索目标时显示轻量空状态，不影响普通搜索和书签浏览。
- 用户在插件内编辑后，才为该书签建立对应额外数据。

### R-012 插件额外数据

storage 只保存浏览器书签没有的字段：

```ts
type BookmarkExtra = {
  bookmarkId: string;
  tags?: string[];
  description?: string;
  searchUrl?: string;
  faviconOverride?: string;
  updatedAt: number;
};
```

书签被删除后必须清理对应额外数据。缺少 extra 时视为空对象，不能阻断展示。

### R-013 favicon 来源

favicon 必须优先使用浏览器已经缓存的图片：

- Chrome / Edge：申请 `favicon` 权限，首选扩展原生 `/_favicon/?pageUrl=<url>&size=<size>`。
- SPA 地址按“精确书签 URL、移除 fragment 的页面 URL、站点根地址”生成缓存候选；精确 URL 必须优先，因为 Chrome 可能为未命中的 `/_favicon` 返回默认图而不触发资源错误，不能让规范化候选抢先遮住真实缓存。
- 不得在页面初始化时对全部书签逐站发起 favicon 网络请求。
- 浏览器原生缓存不可用或返回无效图标时，才进入兼容降级。
- 插件页面每次启动都生成新的 favicon 读取版本，避免页面刷新后重新命中旧默认图。浏览工具区另提供“刷新全部图标”图标按钮；点击后再次更新版本，让所有当前及后续渲染的 `/_favicon` 图片绕过页面图片缓存，重新读取当前浏览器 profile 的 favicon 数据，但不得逐站访问书签 URL。
- 降级顺序必须可控、可取消，并避免对同一域名重复请求。
- 全部来源失败时显示本地默认图标，不显示破图。
- `/_favicon` 只能读取当前浏览器资料中的 favicon 数据；WXT 隔离 Chrome 不共享日常 Chrome 缓存，开发环境使用被忽略且解析为绝对路径的持久 profile，首次访问站点前显示本地占位属于正确降级。
- 手动刷新图标是低频管理动作，不能让普通浏览产生整页闪烁。

除非后续单独确认，不把批量 Base64 favicon 当成普通书签 extra 的默认组成部分。

### R-014 外部变更同步

页面打开期间必须响应浏览器书签的创建、修改、删除、移动和排序事件。插件自身写回后优先增量更新，不能出现整页重载感或全部图标闪烁。

## 4. 主页面

### R-020 浏览态是默认主页

打开主页面后直接进入浏览态并聚焦搜索框。

浏览态必须包含：

- 顶部居中的搜索区域和搜索引擎入口。
- 多列瀑布式目录区。
- 目录内纵向书签行。
- 低干扰的新增、整理和设置入口。
- `#` tag 候选浮层与 `!` 快捷站内搜索浮层。

浏览态不得常驻：

- Logo、产品名或页面用途说明。
- 固定左侧导航栏。
- 浏览 / 整理模式大标签栏。
- 大面积管理工具栏。
- 没有数据时仍占空间的标签区域。

### R-021 目录与书签

目录块：

- 数据仍以浏览器顺序为源；Macy 浏览态按当前最短列重排，避免真实数据下少数列形成明显长尾。
- 标题居中，标题栏可点击折叠；浏览态不显示额外折叠箭头，展开状态由书签内容或 `...` 直接表达。
- 目录标题保持接近 Pages 的紧凑 `36px` 高度，不拉高到一条书签；标题后的内容前距固定 `10px`，加上目录上下各 `1px` 边框后，固定结构恰好为 `48px`。普通书签与折叠占位均为 `48px`，因此含 `n` 条内容的目录总高度严格为 `(n + 1) × 48px`；目录块上下间距为 `24px`，边框相位只允许 `0 / 24px` 两种。
- 浏览态不依赖目录图标、数量徽章或常驻操作按钮建立层级。

书签行：

- 每行固定约 `3rem`；favicon 与约 `1rem` 的标题位于第一行，约 `0.62rem` 的完整 URL 从书签行左缘开始第二行展示。
- 标题使用固定 `1.4rem` 行盒；hover 只在该行盒内对字号做轻微过渡，由浏览器逐帧重新排印文字，不使用会模糊字形的纹理缩放，不得产生上下位移、裁字或书签行高度变化。
- 标题与 URL 均单行省略；URL 不缩进到标题下方。
- 整行点击在新标签页打开。
- 有备注时可通过 hover 和键盘焦点访问，默认不占据行高。
- 标签只在存在 extra 且确有帮助时弱化显示；不能让无标签数据产生空白。

### R-022 折叠

- 每个目录可独立展开 / 收起。
- 提供“全部展开”和“全部收缩”两个图标命令，浏览态放入右下角悬浮工具组，整理态放入整理工具条；使用展开 / 收缩语义图标，不使用容易混淆的上下箭头。目录头不增加箭头，单目录状态仍由书签内容或 `...` 直接表达。
- 搜索命中时不能因目录折叠而隐藏结果。
- 折叠变化后瀑布布局必须稳定重算。
- 全部展开 / 收缩结果写入现有目录偏好，页面刷新后保持。
- 整理工具条按内容紧凑收缩，只保留一层固定外边界；目录 / 书签分段不再嵌套边框，只用选中背景区分，所有命令连续排列且与书签部分保留明确间距。

## 5. 搜索

### R-030 普通搜索

- 搜索框打开页面后自动聚焦。
- 页面未处于其他表单输入或模态时，用户无论当前焦点位于页面何处，直接输入普通字符都必须自动聚焦搜索框并保留本次输入；`Ctrl` / `Cmd` / `Alt` 组合键继续交给快捷键，不得写入搜索框。输入法组合必须由真实搜索输入框承接，不能提前写入拼音字母。
- 匹配目录名、书签标题、URL 和域名；存在 extra 时追加匹配普通标签和备注。
- 匹配不区分大小写，输入首尾空白不参与匹配；连续输入时不改变浏览器书签顺序。
- 普通文本输入只实时过滤主页面中的目录和书签，不展示搜索结果浮层。
- 普通文本按 `Enter` 始终使用当前搜索引擎搜索完整输入；方向键不在隐藏候选中选择书签。
- 过滤后的主页面书签仍可直接点击并在新标签打开；`Esc` 清空查询并恢复完整页面。
- 输入以 `!` / `！` 开头时切换到快捷搜索状态；输入以 `#` 开头时切换到 tag 搜索状态；两者都不再按普通文本解释。
- `!` 快捷候选只列带 `search_site` 的站点目标，不得混入带 `search` 的普通搜索引擎；当前搜索引擎入口继续显示，用于明确站点搜索的实际执行引擎。
- 只有 `#` tag 与 `!` 快捷搜索显示候选浮层，两者共用无外描边表面；普通文本不得复用该浮层。
- 候选浮层不显示教学提示，精确 tag 不使用额外左侧色条或 inset 阴影制造第二种选中语言。
- 搜索下拉必须以搜索框的实时 DOM 边界为唯一定位锚点；初始化、输入变化、引擎切换及搜索下拉重新显示后都要重测，左右边缘和宽度不得受搜索引擎名称宽度影响。
- 候选 hover 使用浅背景，active 使用更明确的 selected 背景；鼠标经过候选必须同步 active 索引，随后方向键从该项继续。长列表滚动不能占用内容宽度，可隐藏原生槽但必须保留滚轮 / 触控滚动。

### R-031 搜索引擎

- 内置 Bing 作为无配置时的可靠回退，可同时提供 Google。
- 带保留标签 `search` 且具有有效搜索模板的书签，作为用户配置的搜索引擎候选。
- 当前选择的 `search` 候选优先；没有当前选择时按浏览器书签顺序取第一个；一个也没有时使用 Bing。
- 空输入和普通文本搜索时，搜索框内的 `↑` / `↓` 都按当前可见引擎顺序循环切换；不得移动隐藏候选或把方向键字符写入输入框。`#` / `!` 状态的方向键仍选择各自候选。
- 引擎选择应贴近 Pages 的“搜索框左侧小入口”，视觉上只保留 favicon 和当前名称；不显示下拉箭头、分隔栏或功能提示。
- 用户已有名称相同的自定义 Bing / Google，或自定义引擎域名属于 `bing.com` / `google.com` 及其子域时，隐藏对应内置项，不能在菜单中重复出现。
- 菜单必须分别表达当前选中项和键盘/鼠标高亮项：使用克制的中性背景与勾选标记，不显示组件库默认焦点外框或双重边框。
- 引擎列表中的 selected 只表示当前已使用引擎，active 表示鼠标或键盘当前目标；二者允许同时出现在不同项。鼠标进入项后，Enter 与方向键必须沿用该 active 位置。
- 鼠标悬浮引擎入口直接打开列表，入口到菜单之间保留短暂关闭缓冲；点击引擎立即切换并关闭，不要求先点击入口再选择。
- 引擎菜单与搜索结果使用同一无描边激活浮层，不显示“内置”等来源说明。
- 引擎入口是主页命令菜单，不使用依赖点击开关的表单 Select；目录等真正的表单字段仍使用成熟 Select 组件。
- 引擎菜单与搜索结果浮层互斥；引擎打开时搜索结果关闭，引擎关闭后仅在查询仍有效时恢复搜索结果，不能同时重叠渲染。

### R-032 叹号快捷搜索语法

英文 `!` 与中文 `！` 完全等价。解析时只把第一个空白前的内容作为目标筛选词，空白后的全部内容作为搜索关键词：

| 输入 | 目标筛选词 | 搜索关键词 | Enter 行为 |
| --- | --- | --- | --- |
| `!` | 空 | 空 | 不执行，只展示全部可用目标 |
| `!目标` | `目标` | 空 | 不执行，只筛选目标 |
| `! 关键词` | 空 | `关键词` | 使用当前选择的目标执行 |
| `!目标 关键词` | `目标` | `关键词` | 从筛选结果中使用当前选择的目标执行 |

- 目标筛选匹配标题、域名和普通标签，不区分大小写。
- 目标列表支持上下键循环选择、鼠标选择和 `Enter`；只有“关键词非空、目标有效”时才能执行。
- 没有明确移动过选择时，Enter 使用列表第一项；列表为空或关键词为空时不得打开页面。
- `Esc` 第一次退出快捷搜索并清空输入；执行后在新标签页打开，当前书签页保持可继续使用。
- 目标只来自用户明确配置的 `search_site` 标签，不能根据标题、域名、`search`、单独存在的 `searchUrl` 或 Pages JSON 猜测快捷目标。
- 普通导入数据没有 tag 和 `searchUrl` 时，目标列表为空是正常状态；空状态不得影响普通搜索。

### R-033 保留 tag 的搜索语义

`search` 与 `search_site` 是不区分大小写的保留 tag，只表达搜索能力，不是普通内容分类：

- `search`：书签是普通搜索引擎，只进入左侧引擎选择，不进入 `!` 快捷候选。必须存在包含 `${keyword}` 或 `{keyword}` 的 `searchUrl`；普通 Enter 搜索时替换占位符，关键词使用 URL 编码。
- `search_site`：书签是站点目标。书签 URL 必须能解析出 HTTP(S) 域名；执行时构造 `site:<domain> <关键词>`，再交给 R-031 解析出的默认搜索引擎。
- `search_site` 不要求也不应自动生成站点自己的搜索地址；例如 V2EX 目标应得到类似 `site:v2ex.com echarts` 的搜索词。
- 同一书签同时含两个保留 tag 时视为配置冲突，不进入目标列表，并在编辑态提示修正。
- `search` 缺少有效模板、`search_site` 缺少有效域名时视为无效配置：不执行、不猜测，并给出局部错误提示。
- 新增或编辑时，由用户显式选择保留 tag 和填写模板；不得仅凭 URL 自动打标或永久保存猜测模板。
- 本插件是新开发项目，不设计旧版插件数据迁移或无 tag 的 `searchUrl` 兼容路径。

### R-034 `#` tag 搜索

`#` 是与 `!` 并列的搜索框命令前缀，tag 筛选不维护第二套独立状态：

| 输入 | tag 候选 | 主内容 |
| --- | --- | --- |
| `#` | 展示全部已有 tag | 展示所有带 tag 的书签 |
| `#xx` 且无同名 tag | 动态匹配 `xx`，例如 `xxx`、`xxy` | 预览包含任一候选 tag 的书签 |
| `#xxx` 且存在同名 tag | 同名项优先 | 自动只显示 tag 精确等于 `xxx` 的书签 |

- `#` 后的完整文本都是 tag 查询词，去除首尾空白后匹配；比较不区分大小写。
- 候选按前缀匹配优先、包含匹配其次，再按书签数量降序和 tag 名称排序。
- 输入变化时同步更新候选浮层和主内容预览；部分匹配多个 tag 时，主内容按候选 tag 的并集预览。
- 查询词与某个已有 tag 完全相等时自动采用精确筛选，不保存搜索框之外的“已选择 tag”状态。
- 上下键切换候选，`Enter` 选择当前候选并把输入框改为其完整 `#tag`；没有候选时 Enter 不执行网络搜索。
- 鼠标点击候选与键盘 Enter 完全等价；精确筛选时输入框中的 `#tag` 是筛选状态的唯一来源。
- 修改精确 `#tag` 后，如果不再完全匹配已有 tag，立即回到动态候选和并集预览。
- `Esc` 优先关闭候选浮层；浮层已关闭时再次按 Esc 清空输入并恢复全部书签。
- 候选来自用户真实保存的全部 tag；`search`、`search_site` 仍可被 `#` 搜索，但在候选中标记为“搜索能力”。
- 没有任何 tag 时，输入 `#` 显示紧凑空状态，不生成假 tag，也不影响清空后的普通搜索。

### R-035 左侧 tag 鼠标入口

- 左侧 tag 列只是 `#` 搜索的鼠标兼容层，不拥有独立筛选状态。
- 只有存在真实 tag 时才显示紧凑入口；默认隐藏 tag 列，鼠标悬浮入口时打开面板，入口到面板之间使用短暂关闭延迟避免闪退；点击和键盘聚焦仍作为触屏与键盘兼容，不挤压或重排目录瀑布流。
- 悬浮面板列出全部 tag 和书签数量，可在面板内按名称过滤；`search`、`search_site` 可单独标记但仍可选择。面板本身无外描边，不设标题栏、分割线或关闭按钮，只保留必要的过滤输入边框和统一激活阴影。
- 点击某个 tag 后，必须模拟同一条搜索输入路径：把搜索框设为 `#<tag>`、由完全匹配规则得出精确筛选、关闭悬浮面板，并把焦点返回搜索框。
- 点击 tag 后产生的结果、URL 状态、键盘行为和直接键入 `#tag` 后选择候选完全相同，不允许维护两份筛选逻辑。
- 点击面板外、再次点击入口或按 Esc 关闭悬浮面板；关闭面板不清除已经写入搜索框的 `#tag`。

### R-036 tag 编辑与创建

书签编辑中的 tag 字段必须使用常见的多选 combobox / token input，不使用“手写逗号字符串”的普通文本框：

- 交互基础使用成熟 Vue 组件库提供的 `TagsInput` + `Combobox` 能力，不自行实现弹层定位、ARIA、键盘导航、输入法判断和焦点循环。
- token 与正在输入的文本必须位于同一个可换行字段、同一个外边框和同一个焦点圈内；不得表现为“已选标签框 + 下方第二个输入框”。
- Combobox 的定位锚点是整个 tag 字段，建议菜单与整个字段同宽，而不是只与剩余输入文字区域同宽。
- 聚焦或输入时显示已有 tag 建议；输入内容实时过滤，前缀匹配优先，其次包含匹配，再按使用次数和名称排序。
- 点击建议或按 `Enter` / `Tab` 选中已有 tag；没有完全匹配项时显示明确的“创建 `<输入>`”动作。
- `Enter`、英文逗号和中文逗号可提交新 tag；从剪贴板粘贴多个逗号或换行分隔值时可批量生成 token。
- 已选 tag 显示为可移除 token；`Backspace` 在输入为空时选中并删除最后一个，鼠标可单独删除。
- tag 创建前去除首尾空白，空值不创建；比较时不区分大小写，禁止重复，但保留首次创建时的显示文字。
- 输入法组合过程中不得被 Enter 或逗号提前提交；建议列表支持上下键、Enter、Esc 和完整键盘焦点。
- `search`、`search_site` 在建议列表中单独归为“搜索能力”，与普通内容 tag 区分；两者互斥。
- 选择 `search` 后显示必填的搜索模板字段；选择 `search_site` 时使用书签 URL 的域名，不显示模板字段；移除 `search` 时同时清理未保存的模板值。
- 新建 tag 保存后立即进入全局 tag 建议与左侧筛选面板，不需要刷新页面。

### R-037 搜索优先级与安全

搜索框始终只有一个输入状态，按以下优先级解释：叹号快捷搜索 > `#` tag 搜索 > 普通文本搜索 > 空输入。

- 叹号和 tag 搜索状态不得同时渲染普通搜索结果，避免 Enter 目标歧义。
- URL 模板只允许替换关键词占位符，不能执行脚本协议或把模板当作任意代码。
- 关键词包含空格、中文或特殊字符时必须正确编码；`search_site` 的 `site:` 结构在整体编码前生成。
- 搜索目标、选择索引和浮层必须随输入同步，目标减少后不得保留越界选择。

## 6. 管理能力

### R-040 低干扰入口

新增、整理、设置和导入导出属于升级能力，但优先级低于浏览。

- 浏览态只保留必要的紧凑图标入口；不可见的 `aria-label` 保留，不以常驻说明、placeholder 或重复状态图标教学。
- tag 与工具入口统一位于左侧短工具轨道：tag 在上、工具在下；没有真实 tag 时工具自动上移到首位。两者默认使用同一弱底板且无边框、无阴影，工具悬浮后向下展开，入口及内容合并为一个统一阴影表面，单个命令不再各自叠加阴影。
- 左右入口都必须兼容悬浮、键盘聚焦和点击打开；Esc 收起后即使指针仍停在入口上，也可通过点击立即重新打开。
- 展开、折叠、刷新、进入整理等直接命令点击后立即执行并收起工具组；添加、设置和导入等确需后续输入的命令点击后直接进入对应单层模态。
- 不用固定侧栏承载管理入口。
- 进入整理态后才展示拖拽把手、编辑、删除和目录操作。
- 退出整理态后必须恢复干净的 Pages 式浏览布局。
- 整理态继续使用顶部搜索和左侧 tag 入口：普通文本过滤目录 / 书签，`#` 过滤 tag，`!` 保留快捷搜索语义；搜索不能成为只保留文字而不执行的装饰控件。
- 查询非空时仍允许拖拽。拖动项必须以筛选结果中的前后可见项为锚点，映射到完整浏览器书签顺序中的真实位置；不可见项保持原相对顺序，不能把筛选列表下标直接写回。
- 书签整理筛选时保留全部目录作为投放目标，只过滤目录内书签；拖入没有可见结果的目标目录时追加到该目录尾部。目录整理筛选时只显示匹配目录，并使用相同的真实锚点映射排序。
- 进入整理态时保存滚动锚点并沿用当前搜索、tag 和目录折叠状态；退出后搜索与折叠状态不被重置，滚动位置合理恢复。

### R-041 书签与目录维护

- 新增、编辑、删除书签。
- 编辑标题、URL、所在目录和可选 extra。
- 编辑时更换目录必须把书签追加到目标目录尾部，不得插入随机位置或沿用源目录索引。
- 新增、重命名、删除目录。
- 删除必须确认，失败不能破坏现有数据。
- 整理态不提供“复制 URL”；复制不属于整理任务，避免与编辑、删除等结构操作混杂。
- 表单和确认弹窗支持 `Esc`，焦点可达。
- Dialog 内的目录 Select、tag Combobox 等 Portal 浮层必须高于遮罩和弹窗内容，不能显示在弹窗下面；Esc 先关闭当前浮层，再处理弹窗。
- Dialog 只使用遮罩、单一白色表面和模态阴影；外层不描边，标题、正文和 footer 不使用独立背景或分割线，内容不再套卡片。
- 表单字段保留单层固定边框；目录 Select 与 tag Combobox 仍通过点击、输入和键盘打开，不因主页悬浮规则而误触，但菜单外观统一为无描边激活浮层。
- 全页面 `Esc` 每次只后退一个交互层级：先关闭当前 Select / Combobox 或模态，再关闭引擎 / tag / 工具浮层，再关闭 `#` / `!` 候选，再清空查询，最后才退出整理态；弹窗关闭不得连带退出整理态。默认态按 Esc 只把焦点还给搜索框，正在执行的数据导入不可中断。

### R-042 拖拽与撤销

- 整理态包含互斥的“目录整理”和“书签整理”子模式，不能让两套拖拽把手和危险操作同时出现。
- 目录整理进入时临时默认全部收缩，收缩项只显示统一高度的目录标题行，不渲染 `...` 或空内容；整体展开 / 收缩和单目录切换仍须保留。书签整理每次进入时临时默认展开全部书签及投放容器；两种状态共用独立临时折叠状态，不得覆盖浏览态偏好。
- 书签拖拽期间鼠标滚轮和边缘自动滚动必须有效；不得使用会吞掉滚轮的原生 HTML5 拖拽路径，浮动拖拽副本应脱离 ScrollArea 内容并将自动滚动目标绑定到页面滚动视口。
- 整理模式-书签使用 Macy，临时收缩目录平时只显示标题行，不显示浏览态 `...` 或常驻空投放区。拖书签靠近收缩目录时，仅该目标动态展开一行高真实 Sortable 投放区并触发重排；离开后收回，放下后目标目录自动展开显示结果。整理模式-目录继续使用等高 Grid，不参与书签动态投放逻辑。
- 目录整理使用正常流响应式 Grid，不使用 Macy 绝对定位。拖动目录以挂到页面浮层的副本跟随指针并脱离 Grid；Grid 内只显示一个随预测索引移动的等高虚线占位槽，其他目录自动补位，松手结果必须与占位位置一致。
- 目录预测顺序和真实写回使用同一结果；写回以目标前后目录的 Chrome 绝对索引为锚点，兼容根目录中夹有直属书签的情况，不得把可见目录下标直接作为浏览器绝对下标。
- 书签整理处理目录内排序和跨目录移动；目录本身不能在此模式被误拖动。
- 拖拽中必须明确显示拖动项、原位置占位、目标目录高亮和插入线；无效区域显示 `not-allowed`，靠近滚动边缘时自动滚动。
- 放下后只锁定相关项和目标目录的重复操作，不使用整页 loading；写回成功给出轻量局部反馈。
- 写回失败必须同时回滚浏览器书签数据、视图顺序和折叠状态，并保留可理解的错误提示。
- 至少支持按钮及 `Ctrl/Cmd+Z` 撤销最近一次成功的移动或排序；输入框、编辑弹窗内的系统撤销优先，不能被全局快捷键截获。
- 拖拽被 `Esc` 取消、落入无效区域或没有产生位置变化时，不写回、不生成撤销记录。
- 浏览态与书签整理使用 Macy：浏览态 `trueOrder: false` 采用最短列优先，书签整理 `trueOrder: true` 按 DOM 顺序保序排布且保持内容自然高度。目录整理因全部目录等高而使用正常流 CSS Grid；Sortable 写回必须可预测。

### R-043 导入导出

首版只保留完整 JSON 备份：

- 导入导出 Dialog 内不再使用“说明卡片 + 分组边框 + 灰色分组标题 + 行分割线”的多层结构；标题下直接排列导出和导入两个操作行，用自然间距组织说明与命令。

- 导出浏览器书签结构、插件 extra 和必要偏好。
- 导入采用增量合并，不清空现有浏览器书签。
- 同名目录合并，新内容追加。
- 完全相同的目录、标题、URL 和 extra 才跳过。
- 普通浏览器导入的数据没有 extra 时按空 extra 处理。
- 无效文件必须零修改失败。

## 7. Popup

### R-050 保存当前页

Popup 用于最短路径收藏：

- 打开主页面。
- 读取当前标签页标题和 URL。
- 搜索并选择目标目录。
- 保存成功后关闭 popup。
- 失败时保留 popup 并显示错误。

存在 bookmarklet 配置时才展示 bookmarklet 模式；不存在时不显示空入口。

## 8. 技术边界

### R-060 技术栈

- WXT。
- Vue 3 + TypeScript。
- 浏览器书签、storage、tabs、favicon 等必要扩展 API。
- SortableJS 处理拖拽。
- Macy 或等价成熟库处理浏览态瀑布布局。
- Reka UI 或经代码审计确认的等价成熟 Vue 无样式组件库，处理 Dialog、Combobox、TagsInput、Select、Popover、Tooltip 和焦点管理。
- lucide 图标用于管理命令，网站 favicon 不用 lucide 替代。

编辑模式不得继续手写完整弹窗、目录下拉或 tag 自动补全。组件库负责可靠行为，项目样式负责 Pages 视觉；不得直接套用后台式默认主题。

### R-061 架构

保持以下边界：

- `bookmarkApi`：浏览器书签 API。
- `extraStore`：插件额外数据。
- `bookmarkRepository`：合成视图与写回。
- `favicon`：浏览器缓存、降级与去重。
- `searchService`：普通搜索、网络搜索和快捷站内搜索。
- `extensionRuntime`：标签页和 popup 行为。
- `importExportService`：完整备份。

### R-062 禁止项

- 不以 mock JSON 或 localStorage 作为书签主数据。
- 不把 Pages JSON 自动混入用户浏览器书签。
- 不根据 URL 猜标签或 `searchUrl`。
- 不在浏览态做固定侧栏和后台仪表盘布局。
- 不用普通卡片网格替代目录瀑布 + 纵向书签行。
- 不在初始化时批量联网抓取全部 favicon。
- 不用自动化小夹具截图替代真实 214 条数据验收。

必须同时满足：

- `DESIGN.md` 中浏览态视觉阻断项通过。

- 类型检查、构建和真实扩展回归通过。
