# 书签浏览器插件需求文档

本文档是 `js/extension/bookmarks` 后续重构的唯一需求基准。旧实现和旧文档仅作为历史参考；新实现必须按浏览器插件方式从头构建，不再继续修补当前 Vite 原型页面。

进度文档后续需要按本文档的需求编号同步记录状态，避免需求、实现和验收口径脱节。

## 1. 项目定位

### R-001 插件定位

做一个高频使用的浏览器书签工作台插件，服务三类动作：

- 快速搜索书签。
- 快速打开书签或站内搜索。
- 快速整理目录和书签。

它不是后台管理系统，不是静态书签页面，也不是先做普通 Web 页面再包装成插件。

### R-002 实现路线

从本轮开始，直接按浏览器插件交付方式实现：

- 必须包含可加载到浏览器的扩展清单。
- 必须使用浏览器书签 API 作为主数据源。
- 必须包含插件入口页面和 popup。
- 构建产物必须能作为浏览器扩展加载验证。

旧代码只可参考交互经验、数据字段和已暴露的问题；不能把旧本地 mock 数据架构继续作为核心实现。

### R-003 设计来源

新前端以 `tmp` 目录下的新设计稿为准：

- `浏览模式 — 卡片视图.html`
- `搜索结果下拉 v2.html`
- `快捷站内搜索 v2.html`
- `整理模式 v2.html`
- `添加_编辑书签 v2.html`
- `添加_编辑目录 v2.html`
- `空状态 _ 无结果 v2.html`

如果旧实现样式与 `tmp` 设计冲突，以 `tmp` 设计为准。

## 2. 产品范围

### R-010 支持的书签范围

首版只支持默认书签位置中的一层目录：

- 读取浏览器默认书签根下的目录。
- 只展示目录内的书签。
- 不支持任意深层嵌套目录。
- 不支持移动端书签、其他设备特殊目录等复杂位置。

如果浏览器书签中存在多层目录，首版可降级为忽略深层目录或只展示一层可用书签，但必须在代码和文档中明确处理口径。

### R-011 主数据源

浏览器原生书签是主数据源：

- 书签标题、URL、目录归属、目录顺序、书签顺序来自浏览器书签。
- 新增、编辑、删除、移动、排序必须写回浏览器书签。
- 插件不能把完整书签树复制到本地 storage 后当作主数据。

### R-012 插件额外数据

插件 storage 只保存浏览器书签没有的额外数据：

- 标签。
- 备注。
- 站内搜索 URL 模板。
- 图标覆盖配置。
- UI 偏好。
- 其他必要扩展字段。

浏览器书签删除后，对应额外数据必须清理。

### R-013 浏览器外部变更同步

当用户在浏览器原生书签管理器、地址栏收藏按钮或其他扩展中修改书签时，本插件必须同步：

- 创建书签。
- 修改标题或 URL。
- 删除书签或目录。
- 移动目录或书签。
- 调整顺序。

页面打开期间应监听变化；页面初始化时必须重新读取浏览器书签树并合成视图。

## 3. 插件页面

### R-020 主页面

主页面是最高频入口，用于浏览、搜索、打开和整理书签。

必须包含：

- 左侧导航和标签区域。
- 顶部浏览 / 整理模式切换。
- 顶部搜索框。
- 搜索引擎选择。
- 新增书签入口。
- 新增目录入口。
- 目录分组书签内容区。
- 搜索结果浮层。
- 站内搜索浮层。
- 空状态和无结果状态。

### R-021 Popup

点击浏览器扩展按钮显示 popup。

必须包含：

- 打开主页面入口。
- 目录搜索框。
- 目录列表。
- 点击目录后将当前标签页保存到该目录。
- bookmarklet 模式入口，仅在存在 bookmarklet 目录或配置时显示。
- bookmarklet 列表，点击后在当前页面执行对应 bookmarklet 并关闭 popup。

操作完成后应关闭 popup，并给出轻量反馈。

### R-022 编辑书签

编辑书签使用设计稿中的弹窗形态。

字段包括：

- 标题。
- URL。
- 所在目录。
- 标签。
- 备注。
- 搜索 URL 模板。

保存时：

- 标题、URL、所在目录写回浏览器书签。
- 标签、备注、搜索 URL 模板写入插件额外数据。

### R-023 添加 / 编辑目录

添加和编辑目录使用设计稿中的弹窗形态。

目录名称写回浏览器书签。目录删除应二次确认；删除目录会删除目录内浏览器书签，属于高风险操作。

### R-024 设置与导入导出

首版可以弱化设置页面，但必须预留入口。

后续需要支持：

- 标准浏览器书签导出格式导入，即常见的 Netscape Bookmark HTML 格式。
- 标准浏览器书签导出格式导出，即可被 Chrome、Edge、Firefox 等浏览器书签管理器导入的 HTML 文件。
- 全量数据导出：浏览器书签 + 插件额外数据。
- 全量数据导入：恢复浏览器书签，并恢复插件额外数据。
- 仅插件额外数据导出。
- 导入插件额外数据并恢复标签、备注、搜索 URL 等字段。

标准书签格式导入导出只处理浏览器书签本体；全量数据导入导出必须同时处理标签、备注、搜索 URL、图标覆盖、UI 偏好等插件额外数据。

## 4. 浏览模式

### R-030 默认浏览体验

打开主页面后默认进入浏览模式。

要求：

- 搜索框默认聚焦。
- 主内容按目录分组展示。
- 书签以设计稿中的轻量卡片形式展示。
- 信息密度接近设计稿，不做大卡片、大留白。
- 编辑、删除、拖拽等低频管理入口默认弱化。

### R-031 书签卡片内容

每个书签至少展示：

- favicon 或可识别的首字母图标。
- 标题。
- URL 或域名信息。
- 标签，最多显示有限数量，避免撑开布局。

完整 URL 数据不能丢失，复制、编辑、提示等场景必须能拿到完整地址。

### R-032 目录分组

每个目录分组至少展示：

- 目录图标。
- 目录名称。
- 书签数量。
- 展开 / 收起状态。

浏览模式下目录标题和书签卡片必须是主要视觉焦点，左侧栏和管理控件不能抢焦点。

### R-033 空状态

必须覆盖：

- 没有任何书签。
- 搜索无结果。
- 目录为空。
- 浏览器书签 API 读取失败。

空状态样式以 `空状态 _ 无结果 v2.html` 为准。

## 5. 搜索

### R-040 普通书签搜索

在搜索框输入普通关键词时：

- 即时过滤书签。
- 匹配标题、URL、标签、备注。
- 显示搜索结果浮层。
- 支持键盘上下选择。
- 支持 Enter 打开高亮结果。
- 支持 Esc 关闭浮层或清空搜索。

搜索结果浮层样式以 `搜索结果下拉 v2.html` 为准。

### R-041 普通网络搜索

当没有选择书签结果，或用户明确触发网络搜索时，使用当前搜索引擎打开搜索结果。

搜索引擎至少支持：

- Google。
- Bing。

后续可扩展更多搜索引擎。

### R-042 快捷站内搜索

输入 `!` 或 `！` 进入快捷站内搜索。

站内搜索必须基于书签的 `searchUrl` 模板，不允许凭站点名称臆造 URL。

交互要求：

- `!站点 关键词` 匹配带 `searchUrl` 的书签。
- 选中站点后，将关键词替换 `searchUrl` 中的 `${keyword}` 或 `{keyword}`。
- 支持键盘选择和 Enter 打开。
- 没有 `searchUrl` 的普通书签不能作为站内搜索目标。

快捷站内搜索样式以 `快捷站内搜索 v2.html` 为准。

## 6. 整理模式

### R-050 进入整理模式

用户显式点击整理后进入整理模式。

整理模式必须与浏览模式视觉上明确区分，但不能变成复杂后台表格。

### R-051 整理模式工具栏

整理模式必须提供：

- 当前处于整理中的状态提示。
- 新增书签。
- 新增目录。
- 目录 / 书签整理切换。
- 撤销最近一次移动或排序。
- 退出整理模式。

样式以 `整理模式 v2.html` 为准。

### R-052 书签整理

书签整理要求：

- 显示拖拽把手。
- 支持目录内排序。
- 支持跨目录移动。
- 支持编辑、删除、复制 URL。
- 操作后写回浏览器书签。
- 操作后更新插件额外数据关联。

### R-053 目录整理

目录整理要求：

- 目录以收缩卡片形态展示。
- 支持目录排序。
- 支持重命名目录。
- 支持删除目录。
- 拖拽过程中反馈清晰，不能出现布局大幅跳动。

### R-054 拖拽反馈

拖拽是核心体验，必须明确：

- 被拖动项半透明。
- 原位置保留占位。
- 可放置目标高亮。
- 插入位置清晰可见。
- 无效区域显示不可放置状态。
- 跨目录拖拽时目标目录进入接收状态。
- 拖到列表顶部或底部时自动滚动。
- 放下后显示短暂成功反馈。
- 支持撤销最近一次拖拽排序或移动。

## 7. 数据与架构

### R-060 浏览器书签 API

必须使用浏览器书签 API：

- `bookmarks.getTree`
- `bookmarks.create`
- `bookmarks.update`
- `bookmarks.remove`
- `bookmarks.removeTree`
- `bookmarks.move`
- `bookmarks.onCreated`
- `bookmarks.onChanged`
- `bookmarks.onRemoved`
- `bookmarks.onMoved`

manifest 必须声明 `bookmarks` 权限。

### R-061 当前标签页 API

popup 保存当前页面时需要读取当前标签页信息。

manifest 需要包含必要权限，例如：

- `activeTab`
- `tabs`，如实现确实需要。

权限使用必须克制，不添加无关权限。

### R-062 数据模型

建议拆分为三层：

```ts
type BrowserBookmarkNode = {
  id: string;
  parentId?: string;
  title: string;
  url?: string;
  index?: number;
  children?: BrowserBookmarkNode[];
};

type BookmarkExtra = {
  bookmarkId: string;
  tags: string[];
  description?: string;
  searchUrl?: string;
  faviconOverride?: string;
  updatedAt: number;
};

type BookmarkView = BrowserBookmarkNode & BookmarkExtra;

type FolderView = {
  id: string;
  title: string;
  index: number;
  bookmarks: BookmarkView[];
  collapsed?: boolean;
};
```

实际类型可调整，但必须保持“浏览器书签数据”和“插件额外数据”分离。

### R-063 服务层

必须拆出服务层，不能把浏览器书签读写、storage 读写和 UI 状态全部塞进单个 Vue 组件。

建议模块：

- `bookmarkApi`：封装浏览器书签 API。
- `extraStore`：封装插件额外数据。
- `bookmarkRepository`：合成视图模型并处理同步。
- `searchService`：普通搜索和快捷站内搜索。
- `extensionRuntime`：处理 popup、当前 tab、扩展页面打开。

## 8. 技术与构建

### R-070 插件构建

构建目标是浏览器扩展产物，而不是普通静态网页。

必须支持：

- 生成 manifest。
- 生成主页面。
- 生成 popup。
- 生成必要的 background/service worker。
- 本地浏览器加载扩展验证。

具体构建工具可在实现前确认，但交付物必须是可加载扩展。

### R-071 前端技术

可继续使用：

- Vue 3。
- TypeScript。
- Element Plus 或同等成熟组件库。
- SortableJS / Vue 拖拽封装。

但组件库默认视觉不能覆盖 `tmp` 设计稿要求。

### R-072 禁止的实现方式

禁止：

- 继续以 mock JSON + localStorage 作为主实现。
- 先做普通 Web 页面，最后再临时套扩展壳。
- 在 `App.vue` 内堆叠全部业务逻辑。
- 手写复杂基础弹窗、菜单、拖拽底层逻辑。
- 把浏览器书签树完整复制到插件 storage 并当作唯一数据源。

## 9. 视觉与交互

### R-080 视觉风格

整体以 `tmp` 设计稿为准：

- MarkHub 风格。
- 浅灰背景。
- 白色浮层。
- 蓝色主色。
- 细边框。
- 低对比阴影。
- 紧凑信息密度。
- 圆角控制在设计稿范围内。

### R-081 明确不要

不要：

- 紫蓝大渐变背景。
- hero 风标题。
- 营销页布局。
- 大面积装饰图形。
- 玻璃拟态。
- 大卡片堆叠。
- 卡片套卡片。
- 过度圆角。
- 低频管理元素常驻抢焦点。

### R-082 响应式

主使用场景是桌面浏览器扩展页面，但仍需保证窄屏不重叠：

- 顶部栏在窄屏可换行。
- 左侧栏在窄屏可隐藏或折叠。
- 卡片网格自适应列数。
- popup 固定宽度内不得横向溢出。

## 10. 验收标准

### R-090 基础验收

首个可用版本必须满足：

- 能作为浏览器扩展加载。
- 主页面能读取真实浏览器书签。
- popup 能读取当前标签页并保存到指定目录。
- 新增、编辑、删除、移动书签能写回浏览器书签。
- 浏览器外部修改能同步到插件视图。
- 插件额外数据只保存扩展字段。
- 构建和类型检查通过。

### R-091 设计验收

必须逐页对照 `tmp` 设计稿：

- 浏览模式。
- 搜索结果下拉。
- 快捷站内搜索。
- 整理模式。
- 添加 / 编辑书签。
- 添加 / 编辑目录。
- 空状态 / 无结果。

验收时需要截图对比，明显偏离设计稿的结构和视觉不得视为完成。

### R-092 交互验收

必须验证：

- 默认聚焦搜索。
- 普通搜索和键盘选择。
- 普通网络搜索。
- 快捷站内搜索。
- 新标签打开书签。
- popup 保存当前页面。
- bookmarklet 执行。
- 书签拖拽排序。
- 跨目录拖拽。
- 目录排序。
- 撤销最近一次移动或排序。
- 删除目录二次确认。

### R-093 风险验收

涉及删除、移动、批量导入等高风险操作时：

- 必须有确认或撤销机制。
- 不得静默删除浏览器书签。
- 出错时必须保留可理解的错误反馈。
