# 书签浏览器插件需求文档

本文档是 `js/extension/bookmarks` 后续重构的唯一需求基准。旧实现和旧文档仅作为历史参考；新实现必须按浏览器插件方式从头构建，不再继续修补当前 Vite 原型页面。

进度文档后续需要按本文档的需求编号同步记录状态，避免需求、实现和验收口径脱节。

## 1. 项目定位

### R-001 插件定位

做一个高频使用的浏览器书签工作台插件，服务三类动作：

- 快速搜索书签。
- 快速打开书签或站内搜索。
- 快速整理目录和书签。

它不是后台管理系统，不是静态书签页面，也不是先做普通 Web 页面再包装成插件。

### R-002 实现路线

从本轮开始，直接按浏览器插件交付方式实现：

- 必须包含可加载到浏览器的扩展清单。
- 必须使用浏览器书签 API 作为主数据源。
- 必须包含插件入口页面和 popup。
- 构建产物必须能作为浏览器扩展加载验证。

旧代码只可参考交互经验、数据字段和已暴露的问题；不能把旧本地 mock 数据架构继续作为核心实现。

### R-003 设计来源

新前端以 `tmp` 目录下的新设计稿为准：

- `浏览模式 — 卡片视图.html`
- `搜索结果下拉 v2.html`
- `快捷站内搜索 v2.html`
- `整理模式 v2.html`
- `添加_编辑书签 v2.html`
- `添加_编辑目录 v2.html`
- `空状态 _ 无结果 v2.html`

如果旧实现样式与 `tmp` 设计冲突，以 `tmp` 设计为准。

### R-004 文档优先防丢失

后续实现过程中，必须把文档当作跨上下文的事实来源。由于长任务、上下文压缩、会话切换可能导致关键信息丢失，任何实际实现或较大调整开始前，必须先更新文档。

需要先写入文档的内容包括：

- 用户新增的临时需求。
- 当前轮准备执行的动作。
- 关键实现决策。
- 已确认的限制和不做事项。
- 可能影响后续实现的上下文。
- 阻塞、风险和待确认问题。

执行顺序要求：

1. 先更新 `REQUIREMENTS.md` 或 `PROGRESS.md`。
2. 再开始修改代码、安装依赖、调整构建或执行实现动作。
3. 如果实现过程中发现需求理解变化，先回写文档，再继续实现。

`REQUIREMENTS.md` 记录稳定需求和执行纪律；`PROGRESS.md` 记录当前动作、临时需求、阶段状态、验证结果和遗留问题。

`PROGRESS.md` 的操作记录必须写入“最近记录”，并按时间倒序排列，最新记录在最上面。不要另开与“最近记录”并列的操作流水区。

每次开始新一轮动作前，都必须先检查并修正 `PROGRESS.md` 当前状态，保证需求状态、里程碑状态、最近记录与真实进展一致；不能带着过期状态进入下一轮实现或测试。

用户已经明确确认“已修复”或“已复测通过”的事项，必须立即同步更新 `PROGRESS.md` 和相关测试文档状态，不能继续保留为 `进行中`、`待修复`、未勾选或其他会误导后续判断的状态。

当前任务的默认工作目录固定为 `js/extension/bookmarks`。后续实现、构建、测试文档维护、版本提交与状态检查，默认都应在该目录视角下进行；除非是为了确认仓库边界，否则不要回到仓库根目录作为日常操作目录。

进度估算采用短周期工作量口径。本阶段按一到两天工作量推进，不使用远期日期式排期；只有提交号、版本、验收事实等需要精确追溯的信息，才记录具体日期或时间。

`PROGRESS.md` 的“最近记录”中，同一时刻只允许保留一个真正进行中的“当前轮”条目。已经做完、已转入历史、或已被后续动作替代的条目，必须改成“已结束：...”或等价结束状态，不能继续保留为“当前轮”。

### R-005 当前阶段测试文档

需要单独维护一份当前阶段测试文档，供用户逐项手工测试和标记结果。

要求：

- 文档独立于 `REQUIREMENTS.md` 和 `PROGRESS.md`。
- 只列出“当前阶段应测试”的功能点，不提前混入后续里程碑内容。
- 每个测试项需要可单独标记。
- 需要明确写出当前不需要测试的范围，避免把后续需求误当成当前阻塞。
- 只有已经实现、已经暴露到当前构建产物中的功能，才能进入“当前可测”清单。
- 尚未实现、尚未接线、或虽然有需求但当前版本还不能稳定触发的内容，必须放入“待实现后补测”区域，不能提前要求用户测试。
- 当阶段范围变化时，先更新该测试文档，再继续实现或让用户测试。
- 用户已确认通过的测试项，必须立即从失败或未完成状态改成通过状态；测试文档不得长期保留与实际结果不一致的勾选状态或结论。

## 2. 产品范围

### R-010 支持的书签范围

首版只支持默认书签位置中的一层目录：

- 读取浏览器默认书签根下的目录。
- 只展示目录内的书签。
- 不支持任意深层嵌套目录。
- 不支持移动端书签、其他设备特殊目录等复杂位置。

如果浏览器书签中存在多层目录，首版可降级为忽略深层目录或只展示一层可用书签，但必须在代码和文档中明确处理口径。

### R-011 主数据源

浏览器原生书签是主数据源：

- 书签标题、URL、目录归属、目录顺序、书签顺序来自浏览器书签。
- 新增、编辑、删除、移动、排序必须写回浏览器书签。
- 插件不能把完整书签树复制到本地 storage 后当作主数据。

### R-012 插件额外数据

插件 storage 只保存浏览器书签没有的额外数据：

- 标签。
- 备注。
- 站内搜索 URL 模板。
- 图标覆盖配置。
- UI 偏好。
- 其他必要扩展字段。

浏览器书签删除后，对应额外数据必须清理。

### R-013 浏览器外部变更同步

当用户在浏览器原生书签管理器、地址栏收藏按钮或其他扩展中修改书签时，本插件必须同步：

- 创建书签。
- 修改标题或 URL。
- 删除书签或目录。
- 移动目录或书签。
- 调整顺序。

页面打开期间应监听变化；页面初始化时必须重新读取浏览器书签树并合成视图。

## 3. 插件页面

### R-020 主页面

主页面是最高频入口，用于浏览、搜索、打开和整理书签。

必须包含：

- 左侧导航和标签区域。
- 顶部浏览 / 整理模式切换。
- 顶部搜索框。
- 搜索引擎选择。
- 新增书签入口。
- 新增目录入口。
- 目录分组书签内容区。
- 搜索结果浮层。
- 站内搜索浮层。
- 空状态和无结果状态。

### R-021 Popup

点击浏览器扩展按钮显示 popup。

必须包含：

- 打开主页面入口。
- 目录搜索框。
- 目录列表。
- 点击目录后将当前标签页保存到该目录。
- bookmarklet 模式入口，仅在存在 bookmarklet 目录或配置时显示。
- bookmarklet 列表，点击后在当前页面执行对应 bookmarklet 并关闭 popup。

操作完成后应关闭 popup，并给出轻量反馈。

### R-022 编辑书签

编辑书签使用设计稿中的弹窗形态。

字段包括：

- 标题。
- URL。
- 所在目录。
- 标签。
- 备注。
- 搜索 URL 模板。

保存时：

- 标题、URL、所在目录写回浏览器书签。
- 标签、备注、搜索 URL 模板写入插件额外数据。

### R-023 添加 / 编辑目录

添加和编辑目录使用设计稿中的弹窗形态。

目录名称写回浏览器书签。目录删除应二次确认；删除目录会删除目录内浏览器书签，属于高风险操作。

### R-024 设置与导入导出

首版可以弱化设置页面，但必须预留入口。

后续需要支持：

- 标准浏览器书签导出格式导入，即常见的 Netscape Bookmark HTML 格式。
- 标准浏览器书签导出格式导出，即可被 Chrome、Edge、Firefox 等浏览器书签管理器导入的 HTML 文件。
- 全量数据导出：浏览器书签 + 插件额外数据。
- 全量数据导入：恢复浏览器书签，并恢复插件额外数据。
- 仅插件额外数据导出。
- 导入插件额外数据并恢复标签、备注、搜索 URL 等字段。

标准书签格式导入导出只处理浏览器书签本体；全量数据导入导出必须同时处理标签、备注、搜索 URL、图标覆盖、UI 偏好等插件额外数据。

## 4. 浏览模式

### R-030 默认浏览体验

打开主页面后默认进入浏览模式。

要求：

- 搜索框默认聚焦。
- 主内容按目录分组展示。
- 书签以设计稿中的轻量卡片形式展示。
- 信息密度接近设计稿，不做大卡片、大留白。
- 编辑、删除、拖拽等低频管理入口默认弱化。

### R-031 书签卡片内容

每个书签至少展示：

- favicon 或可识别的首字母图标。
- 标题。
- URL 或域名信息。
- 标签，最多显示有限数量，避免撑开布局。

完整 URL 数据不能丢失，复制、编辑、提示等场景必须能拿到完整地址。

### R-032 目录分组

每个目录分组至少展示：

- 目录图标。
- 目录名称。
- 书签数量。
- 展开 / 收起状态。

浏览模式下目录标题和书签卡片必须是主要视觉焦点，左侧栏和管理控件不能抢焦点。

### R-033 空状态

必须覆盖：

- 没有任何书签。
- 搜索无结果。
- 目录为空。
- 浏览器书签 API 读取失败。

空状态样式以 `空状态 _ 无结果 v2.html` 为准。

## 5. 搜索

### R-040 普通书签搜索

在搜索框输入普通关键词时：

- 即时过滤书签。
- 匹配标题、URL、标签、备注。
- 显示搜索结果浮层。
- 支持键盘上下选择。
- 支持 Enter 打开高亮结果。
- 支持 Esc 关闭浮层或清空搜索。

搜索结果浮层样式以 `搜索结果下拉 v2.html` 为准。

### R-041 普通网络搜索

当没有选择书签结果，或用户明确触发网络搜索时，使用当前搜索引擎打开搜索结果。

搜索引擎至少支持：

- Google。
- Bing。

后续可扩展更多搜索引擎。

### R-042 快捷站内搜索

输入 `!` 或 `！` 进入快捷站内搜索。

站内搜索必须基于书签的 `searchUrl` 模板，不允许凭站点名称臆造 URL。

交互要求：

- `!站点 关键词` 匹配带 `searchUrl` 的书签。
- 选中站点后，将关键词替换 `searchUrl` 中的 `${keyword}` 或 `{keyword}`。
- 支持键盘选择和 Enter 打开。
- 没有 `searchUrl` 的普通书签不能作为站内搜索目标。

快捷站内搜索样式以 `快捷站内搜索 v2.html` 为准。

### R-043 搜索框统一输入逻辑

搜索框只有两种模式：普通搜索模式、快捷站内搜索模式。模式只由输入内容决定，不允许出现第三种隐含模式。

#### 普通搜索模式

满足以下条件时进入普通搜索模式：

- 输入为空。
- 输入不以 `!` 或 `！` 开头。

普通搜索模式规则：

- 空输入时不显示搜索结果浮层。
- 非空输入时显示普通搜索结果浮层。
- 结果集由“当前搜索引擎结果项 + 书签命中项”组成，搜索引擎结果固定放在第一行。
- 搜索范围包括标题、URL、标签、备注。
- `ArrowDown` / `ArrowUp` 在当前结果集中移动高亮。
- 默认高亮第一行搜索引擎结果；用户未手动移动选择时，`Enter` 直接触发当前搜索引擎搜索。
- 用户手动切换高亮后，`Enter` 打开当前高亮项。
- `Esc` 清空输入并关闭浮层。

#### 快捷站内搜索模式

输入以 `!` 或 `！` 开头时进入快捷站内搜索模式。

快捷站内搜索模式下，只允许使用带 `searchUrl` 的书签作为目标站点。

输入语法必须固定为以下两种：

1. `!筛选词`
2. `!筛选词 搜索内容`

语义定义：

- 只有一个前缀 `!` / `！`，后面没有空格分段时：
  - 前缀后的全部内容都视为“站点筛选词”。
  - 搜索内容为空。
  - 只根据筛选词过滤站点列表。
  - 此时 `Enter` 无效，因为还没有搜索内容。
- 出现“前缀后第一段 + 空格 + 后续内容”时：
  - 第一段视为“站点筛选词”。
  - 空格后的剩余内容视为“搜索内容”。
  - 第一个空格后的内容全部视为搜索内容，不再参与站点筛选。
- 单独输入 `!` / `！` 时：
  - 搜索内容为空。
  - 不做站点筛选。
  - 直接展示全部带 `searchUrl` 的站点列表。

- 如果输入是 `! 搜索内容`：
  - 站点筛选词为空。
  - 第一个空格后的内容视为搜索内容。
  - 直接在“全部带 `searchUrl` 的站点列表”上操作。

快捷站内搜索模式规则：

- 站点筛选只匹配站点标题、域名、标签，不匹配搜索内容。
- 搜索内容只用于最终替换 `searchUrl` 模板，不参与站点筛选。
- `ArrowDown` / `ArrowUp` 在当前站点列表中移动高亮。
- 只有搜索内容非空时，`Enter` 才使用当前高亮站点和当前搜索内容生成最终 URL 并打开。
- 搜索内容为空时，`Enter` 无效，不打开任何目标。
- `Esc` 清空输入并关闭浮层。
- 如果没有任何可用站点，显示空结果态，不回退到普通搜索。

## 6. 整理模式

### R-050 进入整理模式

用户显式点击整理后进入整理模式。

整理模式必须与浏览模式视觉上明确区分，但不能变成复杂后台表格。

### R-051 整理模式工具栏

整理模式必须提供：

- 当前处于整理中的状态提示。
- 新增书签。
- 新增目录。
- 目录 / 书签整理切换。
- 撤销最近一次移动或排序。
- 退出整理模式。

样式以 `整理模式 v2.html` 为准。

### R-052 书签整理

书签整理要求：

- 显示拖拽把手。
- 支持目录内排序。
- 支持跨目录移动。
- 支持编辑、删除、复制 URL。
- 操作后写回浏览器书签。
- 操作后更新插件额外数据关联。

### R-053 目录整理

目录整理要求：

- 目录以收缩卡片形态展示。
- 支持目录排序。
- 支持重命名目录。
- 支持删除目录。
- 拖拽过程中反馈清晰，不能出现布局大幅跳动。

### R-054 拖拽反馈

拖拽是核心体验，必须明确：

- 被拖动项半透明。
- 原位置保留占位。
- 可放置目标高亮。
- 插入位置清晰可见。
- 无效区域显示不可放置状态。
- 跨目录拖拽时目标目录进入接收状态。
- 拖到列表顶部或底部时自动滚动。
- 放下后显示短暂成功反馈。
- 支持撤销最近一次拖拽排序或移动。

## 7. 数据与架构

### R-060 浏览器书签 API

必须使用浏览器书签 API：

- `bookmarks.getTree`
- `bookmarks.create`
- `bookmarks.update`
- `bookmarks.remove`
- `bookmarks.removeTree`
- `bookmarks.move`
- `bookmarks.onCreated`
- `bookmarks.onChanged`
- `bookmarks.onRemoved`
- `bookmarks.onMoved`

manifest 必须声明 `bookmarks` 权限。

### R-061 当前标签页 API

popup 保存当前页面时需要读取当前标签页信息。

manifest 需要包含必要权限，例如：

- `activeTab`
- `tabs`，如实现确实需要。

权限使用必须克制，不添加无关权限。

### R-062 数据模型

建议拆分为三层：

```ts
type BrowserBookmarkNode = {
  id: string;
  parentId?: string;
  title: string;
  url?: string;
  index?: number;
  children?: BrowserBookmarkNode[];
};

type BookmarkExtra = {
  bookmarkId: string;
  tags: string[];
  description?: string;
  searchUrl?: string;
  faviconOverride?: string;
  updatedAt: number;
};

type BookmarkView = BrowserBookmarkNode & BookmarkExtra;

type FolderView = {
  id: string;
  title: string;
  index: number;
  bookmarks: BookmarkView[];
  collapsed?: boolean;
};
```

实际类型可调整，但必须保持“浏览器书签数据”和“插件额外数据”分离。

### R-063 服务层

必须拆出服务层，不能把浏览器书签读写、storage 读写和 UI 状态全部塞进单个 Vue 组件。

建议模块：

- `bookmarkApi`：封装浏览器书签 API。
- `extraStore`：封装插件额外数据。
- `bookmarkRepository`：合成视图模型并处理同步。
- `searchService`：普通搜索和快捷站内搜索。
- `extensionRuntime`：处理 popup、当前 tab、扩展页面打开。
- `importExportService`：处理标准书签 HTML、全量数据和插件额外数据的导入导出。

## 8. 技术与构建

### R-070 插件构建

构建目标是浏览器扩展产物，而不是普通静态网页。

本项目后续使用 WXT 作为浏览器插件构建框架。WXT 负责扩展入口发现、manifest 生成、开发调试和扩展产物输出；不再维护手写 Vite 多入口扩展壳。

必须支持：

- 生成 manifest。
- 生成主页面。
- 生成 popup。
- 生成必要的 background/service worker。
- 本地浏览器加载扩展验证。

交付物必须是可加载扩展。WXT 配置、entrypoints 结构和构建脚本必须写入仓库。

### R-071 前端技术

使用：

- WXT。
- Vue 3。
- TypeScript。
- SortableJS / Vue 拖拽封装。
- lucide 图标。

如后续引入 Element Plus 或同等成熟组件库，组件库默认视觉不能覆盖 `tmp` 设计稿要求。

### R-072 禁止的实现方式

禁止：

- 继续以 mock JSON + localStorage 作为主实现。
- 先做普通 Web 页面，最后再临时套扩展壳。
- 在 `App.vue` 内堆叠全部业务逻辑。
- 手写复杂基础弹窗、菜单、拖拽底层逻辑。
- 把浏览器书签树完整复制到插件 storage 并当作唯一数据源。

## 10. 里程碑

里程碑用于中途直接测试，避免全部做完后才集中发现问题。每个里程碑必须满足“可加载、可操作、可判断是否通过”三项要求；未通过当前里程碑前，不进入下一个里程碑的完成判定。

### M-01 扩展骨架可加载

目标：先确认扩展工程、入口和构建链正确，再继续堆业务。

通过标准：

- `npm run build` 通过。
- 能加载 `.output/chrome-mv3/` 扩展产物。
- 浏览器扩展按钮可见。
- 点击扩展按钮能打开 popup。
- 能从 popup 打开主页面。
- 无白屏、无明显脚本报错、无 manifest 权限错误。

测试方式：

- 加载未打包扩展或构建产物。
- 手动打开 popup 和主页面。
- 检查控制台和扩展错误页。

### M-02 真实书签只读打通

目标：先确认插件确实读取的是浏览器真实书签，而不是本地 mock。

通过标准：

- 主页面能读取默认书签位置的一层目录。
- 能展示目录分组、书签标题、域名和基础卡片。
- 搜索框默认聚焦。
- 浏览器书签为空、无结果、API 失败三类状态至少能人工触发并看到对应空状态之一。

测试方式：

- 准备若干真实目录和书签。
- 打开主页面验证展示结果。
- 用浏览器原生书签管理器修改数据，刷新页面验证重新读取。

### M-03 Popup 保存当前页可用

目标：先确认高频入口能用，再继续做复杂编辑和整理。

通过标准：

- popup 能读取当前标签页标题和 URL。
- popup 能搜索目录。
- 点击目录后，当前页能保存到对应浏览器书签目录。
- 保存完成后 popup 自动关闭或给出轻量反馈。
- 回到浏览器原生书签管理器可看到新增书签。

测试方式：

- 打开任意网页。
- 从 popup 保存到指定目录。
- 对照浏览器原生书签结果验证。

### M-04 书签搜索与站内搜索可用

目标：先把最核心的搜索闭环打通。

通过标准：

- 普通关键词能搜索书签标题、URL、标签、备注。
- 搜索结果浮层可见，支持键盘上下和 Enter。
- Google/Bing 网络搜索入口可触发。
- `!` / `！` 快捷站内搜索可用。
- 站内搜索只使用 `searchUrl` 模板生成目标 URL。

测试方式：

- 准备带标签、备注、`searchUrl` 的真实或导入数据。
- 分别验证普通搜索、网络搜索和快捷站内搜索。

### M-05 书签编辑写回可用

目标：先验证增删改能真实写回浏览器书签和额外数据。

通过标准：

- 可新增书签。
- 可编辑标题、URL、所在目录。
- 可保存标签、备注、搜索 URL 模板。
- 删除书签后，浏览器书签本体删除，额外数据同步清理。
- 刷新页面后数据不丢失。

测试方式：

- 在主页面创建、编辑、删除书签。
- 对照浏览器原生书签和插件展示结果验证。

### M-06 整理模式最小闭环

目标：先验证整理模式不是静态样式，而是真能改顺序和归属。

通过标准：

- 能进入和退出整理模式。
- 目录和书签出现整理态控件。
- 至少支持目录内排序和跨目录移动。
- 操作后写回浏览器书签顺序或目录归属。
- 最近一次移动或排序可撤销一次。

测试方式：

- 在整理模式拖拽多个书签。
- 刷新页面并在浏览器原生书签管理器核对顺序。

### M-07 导入导出最小闭环

目标：先确认数据迁移能力可用，再继续做完整设置页。

通过标准：

- 标准 Netscape Bookmark HTML 可导入。
- 标准浏览器书签 HTML 可导出。
- 全量数据可导出并重新导入。
- 插件额外数据可单独导出和导入。
- 导入失败时有明确错误反馈，不静默破坏现有数据。

测试方式：

- 导出一份标准书签 HTML。
- 导入测试文件。
- 导出全量数据后清空测试目录，再回导验证。

### M-08 首版综合验收

目标：作为首个可交付测试版本。

通过标准：

- 满足 `R-090`、`R-091`、`R-092`、`R-093`。
- 主页面、popup、编辑弹窗、整理模式、搜索浮层均完成对照测试。
- 最近记录和需求状态已回写最终测试结果与遗留问题。

测试方式：

- 按综合验收清单逐项人工测试。
- 输出截图、验证结论和遗留问题。

## 11. 验收标准

### R-090 基础验收

首个可用版本必须满足：

- 能作为浏览器扩展加载。
- 主页面能读取真实浏览器书签。
- popup 能读取当前标签页并保存到指定目录。
- 新增、编辑、删除、移动书签能写回浏览器书签。
- 浏览器外部修改能同步到插件视图。
- 插件额外数据只保存扩展字段。
- 构建和类型检查通过。

### R-091 设计验收

必须逐页对照 `tmp` 设计稿：

- 浏览模式。
- 搜索结果下拉。
- 快捷站内搜索。
- 整理模式。
- 添加 / 编辑书签。
- 添加 / 编辑目录。
- 空状态 / 无结果。

验收时需要截图对比，明显偏离设计稿的结构和视觉不得视为完成。

### R-092 交互验收

必须验证：

- 默认聚焦搜索。
- 普通搜索和键盘选择。
- 普通网络搜索。
- 快捷站内搜索。
- 新标签打开书签。
- popup 保存当前页面。
- bookmarklet 执行。
- 书签拖拽排序。
- 跨目录拖拽。
- 目录排序。
- 撤销最近一次移动或排序。
- 删除目录二次确认。

### R-093 风险验收

涉及删除、移动、批量导入等高风险操作时：

- 必须有确认或撤销机制。
- 不得静默删除浏览器书签。
- 出错时必须保留可理解的错误反馈。

## 12. 后续进度文档对齐方式

后续 `PROGRESS.md` 必须按本文档编号记录：

- 状态：未开始 / 进行中 / 待测试 / 待修复 / 已完成 / 暂缓 / 阻塞。
- 实现文件。
- 验证方式。
- 验证结果。
- 遗留问题。

状态定义：

- `未开始`：还没有进入实现。
- `进行中`：正在实现，功能或结构还未收口。
- `待测试`：实现已进入当前构建产物，但还需要人工测试或真实环境验证。
- `待修复`：已经测出问题，必须修完再继续推进。
- `已完成`：实现和当前阶段验收都已通过。
- `暂缓`：明确延后，不在当前阶段推进。
- `阻塞`：受外部条件限制，当前无法继续。

操作流水必须写在“最近记录”中，并遵守：

- 最新记录放在最上面。
- 记录用户临时需求、准备执行的动作、已完成动作、验证结果和遗留风险。
- 排期使用短周期工作量描述，本阶段约一到两天，不使用远期日期标题。
- 只能有一个“当前轮”处于进行中；旧条目必须改成已结束状态。
- 每次进入新一轮前，先校正文档状态；凡是用户已确认修复、已确认通过、已转入历史的事项，必须先回写，再继续下一步动作。

里程碑也必须在 `PROGRESS.md` 中单独记录：

- 编号：`M-01` 至 `M-08`。
- 状态：未开始 / 进行中 / 待测试 / 待修复 / 已完成 / 暂缓 / 阻塞。
- 当前可直接测试的入口或操作。
- 测试结果。
- 是否允许进入下一个里程碑。

测试文档也必须区分：

- `当前可测`：已经实现，用户现在就能操作验证。
- `待实现后补测`：需求已存在，但当前构建还不能稳定测试。

示例：

```text
R-060 浏览器书签 API：进行中
实现文件：src/services/bookmarkApi.ts
验证方式：加载扩展后读取真实书签树
验证结果：待验证
遗留问题：Firefox polyfill 兼容性未确认
```
