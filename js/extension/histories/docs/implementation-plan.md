# Histories 第一阶段整体实施计划

更新日期：2026-08-21

产品范围和验收口径以 [第一阶段需求基线](requirements.md) 为准。本计划是第一阶段唯一执行清单，只规定实现顺序、交付物和验收门槛，不扩大产品范围。

## 计划规则

### 状态

- `已完成`：代码、测试、验证记录和验收条件全部完成。
- `进行中`：当前正在实施，尚未达到全部通过条件。
- `待开始`：依赖尚未完成或尚未进入实施。
- `阻塞`：存在明确外部阻塞，必须记录证据、影响和恢复条件。

### 完成定义

每个编号任务只有同时满足以下条件才能标记为已完成：

1. 产物已经进入正式源码或文档，不依赖临时脚本维持。
2. 正常路径、重复执行和中断恢复路径均有对应测试或真实浏览器证据。
3. 私有 HTU 数据、浏览器 profile、日志和构建输出未进入版本库。
4. TypeScript、相关单元测试、浏览器测试以及 Chrome/Firefox 构建通过。
5. 行为或性能结论已经写入 [验证记录](verification.md)。

### 执行顺序

```text
0. 已有技术基线
  -> 1. 架构门槛验证
  -> 2. 统一可靠主数据
  -> 3. 多 HTU 合并导入
  -> 4. 浏览器历史完整采集
  -> 5. 增量搜索与稳定分页
  -> 6. 完整导出与恢复
  -> 7. 第一阶段界面
  -> 8. 双浏览器长期验收
```

阶段依赖原则：数据模型完成前不扩展导入和采集；主数据闭环完成前不把索引当作权威状态；可靠性和恢复能力完成前不以页面完成度作为阶段完成依据。

## 0. 已有技术基线

状态：`已完成`

### 0.1 HTU 格式与原型

- 支持解析 HTU 3、4、8 列 TSV，以及旧 Windows epoch 和 `U<unix_ms>` 时间格式。
- 已有单文件导入、chunk 构建、4 列 HTU 导出和字节级往返测试。
- 已确认同步和 HTU 导入均排除 `data:image/...`，只保留聚合忽略数量。

### 0.2 存储与搜索路线

- IndexedDB 作为持久事实来源。
- SQLite WASM `:memory:` + FTS5 trigram 作为标题和 URL 的三字符连续子串索引。
- SQLite 快照保存到 IndexedDB；索引允许删除并从主数据重建。
- SQLite OPFS 不作为跨浏览器依赖。

### 0.3 大数据和增量性能

- 已完成约 90 万访问、约 38 万 URL 的真实 HTU 数据验证。
- 首次 FTS 建立约几十秒，快照约 `568 MiB`。
- 最近 7 天 `2,264` 条访问的 dirty replay 约 `407 ms`。
- 已确认既有 URL 仅新增访问时不应更新 FTS；完整 checkpoint 只能低频执行。

### 0.4 工程基线

- WXT Chrome MV3 和 Firefox MV3 构建通过。
- 核心存储、HTU、搜索及 worker 已有自动化烟测。
- `dev-browser-data/chromium/` 和 `dev-browser-data/firefox/` 用于持久人工验收，内容不提交。

3. `1.1.3` 在 Firefox 扩展页面重复相同流程。
4. `1.1.4` 记录 `navigator.storage.estimate()`、持久存储授权结果、快照保存时间和加载时间。

产物：扩展环境大数据测试入口、聚合结果和 Chrome/Firefox 配额结论。

通过条件：两个目标浏览器都能可靠保存和恢复完整快照；如果任一浏览器不能满足，必须先确定分片快照、压缩、延迟重建或其他不损害主数据的降级方案。

### 1.2 时间倒序分页基准

5. `1.2.5` 对比游标分页和有限 offset 分页，记录耗时、扫描数量和内存。

产物：可重复分页基准和最终查询计划。

通过条件：常见第一页目标低于 `100 ms`；连续翻页无重复、无跳项；深分页策略有明确上限或稳定游标实现。

### 1.3 双通道访问字段验证

1. `1.3.1` 在 Chrome 记录同一次真实访问的 `history.onVisited` 和 `history.getVisits` 字段。
2. `1.3.2` 在 Firefox 记录同一组字段和差异。
3. `1.3.3` 覆盖链接跳转、地址栏输入、刷新、前进后退和重定向。
4. `1.3.4` 只保存脱敏结构和聚合结果，不记录私人 URL 或标题。
5. `1.3.5` 确定浏览器事件、补偿扫描和 HTU 行的规范访问身份及来源关联规则。

产物：跨浏览器字段矩阵、去重决策和自动化固定样本。

通过条件：去重不再依赖单次任务 ID 或 `sourceIndex`；相同访问可跨实时事件、补偿扫描和任务重试稳定识别。

### 1.4 架构决策冻结

任务：

2. `1.4.2` 明确主数据物理结构、索引快照策略和任务所有者。
3. `1.4.3` 建立后续数据库升级所需的格式版本号。

通过条件：阶段 2 不再存在会改变主存储结构的未决问题。

## 2. 统一可靠主数据

状态：`已完成`

目标：建立唯一、可迁移、可恢复的访问事实来源，消除大批量 chunk 与小批量 record 两套语义分裂。

### 2.1 数据模型与版本

1. `2.1.1` 定义规范页面、规范访问、访问来源、导入批次、同步游标、任务和 dirty page 模型。
2. `2.1.2` 区分不可丢失的主数据与可重建的页面聚合、统计和搜索快照。
3. `2.1.3` 设计适合 90 万以上访问的分块编码、稳定 ID 和时间索引。
4. `2.1.4` 增加数据库、主数据编码、原生备份和搜索快照版本。
5. `2.1.5` 实现旧原型数据到新模型的迁移或明确的一次性重导路径。

### 2.2 统一写入协议

1. `2.2.1` 实现单条和批量访问共用的规范化、幂等去重及提交入口。
2. `2.2.2` 支持隔离批次、提交标记和失败回滚或等价的不可见半成品机制。
3. `2.2.3` 先提交访问数据，再推进同步游标和任务状态。
4. `2.2.4` 标题或 URL 搜索文本变化时持久记录 dirty page。
5. `2.2.5` 所有写入入口统一排除 `data:image/...` 并只累计忽略数量。

### 2.3 可恢复任务

1. `2.3.1` 将导入、同步、索引重建和导出任务状态移出页面生命周期。
2. `2.3.2` 保存阶段、游标、进度、错误、重试次数和输入身份。
3. `2.3.3` 页面关闭、worker 终止和浏览器重启后可以恢复或安全重试。
4. `2.3.4` 同一任务重放不能重复提交访问。

### 2.4 存储可靠性测试

1. `2.4.1` 覆盖空库、旧库升级、大批量写入和增量追加。
2. `2.4.2` 在解析、分块、提交和游标推进各阶段注入中断。
3. `2.4.3` 校验恢复前后访问集合和聚合计数。
4. `2.4.4` 校验删除搜索快照不影响主数据读取。

通过条件：关键写入被强制中断后旧数据完整；重试结果幂等；导入和浏览器采集使用同一事实模型。

完成记录（2026-08-17）：数据库 v6 已统一使用不可变 page/visit segments 和 staging/active generation。激活事务分配单调 revision、切换 active pointer 并写入 dirty page；旧 v5 records/chunks 保留只读回退。默认 HTU 导入与浏览器同步均发布 generation。浏览器来源实例持久保存，来源键使用 `(sourceInstanceId, visitId)`，跨来源仍按 URL、时间和 transition 指纹去重。烟测覆盖 staging 写入中断、激活前失败、同步发布前失败、游标仅在发布后推进、租约接管/释放、旧库升级和 generation 清理；搜索重建 worker 已改为读取 active generation。

## 3. 多 HTU 文件合并导入

状态：`已完成`

目标：完整、安全地汇总多个浏览器和多个时间点导出的 HTU 数据。

### 3.1 多文件输入与预检

1. `3.1.1` 支持一次选择多个文件以及向待导入列表追加文件。
2. `3.1.2` 流式计算文件 SHA-256、格式、行数和时间范围。
3. `3.1.3` 全部文件结构校验通过后才进入正式合并。
4. `3.1.4` 文件级错误不得阻止用户识别具体失败文件。

### 3.2 全局合并与幂等

1. `3.2.1` 将全部输入写入隔离导入批次。
2. `3.2.2` 按规范访问身份进行全局排序和去重。
3. `3.2.3` 与已有主库合并，不清空、不覆盖历史数据。
4. `3.2.4` 保留每次访问的标题、transition、时间和来源文件关联。
5. `3.2.5` HTU 导入不应用频繁访问抑制。
6. `3.2.6` 提交完成后统一更新页面聚合并重建或批量更新索引。

### 3.3 导入报告与恢复

1. `3.3.1` 保存每个文件和整体的输入、新增、重复、忽略、错误数量。
2. `3.3.2` 保存批次 ID、文件哈希、源标签、时间和最终状态。
3. `3.3.3` 支持取消、失败后重试和页面重新打开后查看结果。

### 3.4 验收矩阵

1. `3.4.1` 同一文件连续导入两次，第二次新增为零。
2. `3.4.2` 多个重叠文件按不同顺序导入，最终规范访问集合一致。
3. `3.4.3` 3、4、8 列和两种时间格式交叉覆盖。
4. `3.4.4` 混入 `data:image/...`、坏行、重复行和取消操作。
5. `3.4.5` 使用真实约 90 万访问备份及裁剪增量文件完成浏览器回归。

通过条件：多文件导入完全幂等、顺序无关、中断安全，且不覆盖已有主数据。

完成记录（2026-08-17）：支持一次传入多个精确字节文件，逐文件计算 SHA-256、识别 3/4/8 列格式、统计时间范围并在任何文件错误时整批拒绝。空库使用扁平排序快速合并，非空库与 active generation 合并；访问指纹为精确 URL、时间和 transition，文件内、文件间、既有库间统一去重。visit chunk 使用来源字典、offset 和扁平引用保留多文件来源。来源和批次报告持久化，取消/预检失败/发布失败不改变 active generation。真实备份裁成“去掉最近 7 天”的基线和带 7 天重叠的 14 天增量：基线新增 `897,913`，增量新增 `2,264`、重复 `1,899`，再次增量新增为零，最终 `900,177` 次访问；三次导入分别约 `4.0s`、`3.0s`、`3.1s`。

## 4. 浏览器历史完整采集

状态：`已完成`

目标：尽量完整记录浏览器已有历史和后续访问，同时避免双通道重复。

### 4.1 首次和补偿扫描

1. `4.1.1` 首次运行扫描浏览器可访问的全部历史。
2. `4.1.2` 打开历史页时从已提交游标执行增量补偿扫描。
3. `4.1.3` 分页读取并限制单事务大小，保存可恢复进度。
4. `4.1.4` 忽略未来偏移异常记录，游标保留安全重叠窗口。

完成记录（2026-08-21）：首次安装全量扫描、启动/历史页补偿扫描、固定批次分页和同时间边界扫描均已实现；同步游标保留 5 秒安全重叠窗口并过滤未来偏移。Chrome/Firefox 正式扩展均验证实时 onVisited、持久化和同 profile 重启恢复；分页单测覆盖同时间边界无漏项。

### 4.2 实时监听

1. `4.2.1` 后台接入 `history.onVisited`。
2. `4.2.2` 实时事件立即进入统一写入协议。
3. `4.2.3` 补偿扫描再次发现同一访问时只关联来源，不新增访问。
4. `4.2.4` 不监听也不响应浏览器删除历史事件。

完成记录（2026-08-21）：后台注册 `history.onVisited`，以精确 URL 合并 250ms 内事件并调用 `getVisits` 补全；实时、补偿和手工同步共用串行发布队列，避免 generation 分叉覆盖。浏览器来源使用持久 `sourceInstanceId` 和 native `visitId`。

### 4.3 频繁访问抑制

1. `4.3.1` 在采集幂等之后按同一精确 URL 和时间顺序应用阈值。
2. `4.3.2` 默认 `2.0` 秒，`0` 表示不抑制不同访问。
3. `4.3.3` 设置只影响浏览器实时和补偿采集。
4. `4.3.4` 报告幂等重复和频繁访问抑制的独立计数。

当前实现：merge 阶段先按来源键/URL+时间+transition 幂等去重，再按同一精确 URL 的时间序列应用阈值；阈值 `0` 不抑制；HTU 导入不经过该逻辑。核心测试覆盖默认阈值和关闭阈值、重复来源关联及 data-image 计数。

### 4.4 生命周期与回归

1. `4.4.1` 测试 Chrome MV3 service worker 回收和浏览器重启。
2. `4.4.2` 测试 Firefox 后台生命周期和长时间未打开扩展后的补偿。
3. `4.4.3` 对照浏览器历史进行集合级和抽样级遗漏、重复检查。
4. `4.4.4` 如果双通道不能稳定去重，记录证据并回退到打开页面增量扫描。

通过条件：双通道重复发现只保存一条，后台中断后能够补齐；默认阈值和阈值 `0` 均符合需求定义。

## 5. 增量搜索与稳定分页

状态：`已完成`

目标：在日常新增数据下维持快速三字符子串搜索、时间过滤和稳定翻页。

### 5.1 索引生命周期

1. `5.1.1` 启动时加载最近完整 checkpoint。
2. `5.1.2` 批量重放持久 dirty page，使索引追上主库修订号。
3. `5.1.3` 新 URL 或搜索文本变化时更新 FTS；仅新增访问不改写 FTS。
4. `5.1.4` 按 dirty 数量、时间和空闲状态生成低频 checkpoint。
5. `5.1.5` 保存快照版本、主库修订号、页数、大小和校验信息。

### 5.2 查询语义

1. `5.2.1` 搜索标题、原始 URL 和安全解码 URL。
2. `5.2.2` 标准化后少于 3 个字符不执行子串查询。
3. `5.2.3` 支持起始时间、结束时间和完整时间范围。
4. `5.2.4` FTS 只返回候选页面；访问次数、匹配时间和排序来自主数据。
5. `5.2.5` 无关键词时直接使用访问时间索引。

### 5.3 稳定分页

1. `5.3.1` 实现阶段 1 冻结的稳定游标或受限 offset 方案。
2. `5.3.2` 页面结果按范围内最近匹配访问时间倒序。
3. `5.3.3` 同一查询连续分页不得重复或漏项。
4. `5.3.4` 数据在翻页期间新增时，使用查询水位或等价机制保持会话稳定。

### 5.4 索引故障恢复

1. `5.4.1` 检测快照缺失、版本不兼容、校验失败和 SQLite 加载错误。
2. `5.4.2` 标记索引不可用但保持主数据可读。
3. `5.4.3` 支持后台全量重建、进度展示和安全重试。
4. `5.4.4` 重建前后固定查询结果一致。

通过条件：真实大备份规模下常见查询低于 `100 ms`，时间倒序分页稳定，日常增量不触发全量重建。

完成记录（2026-08-21）：生产历史页启动时加载带 SHA-256 的最近 checkpoint，批量回放持久 dirty page；只有 checkpoint 成功后才清除 dirty，失败时保留以供重试。仅新增访问而搜索文本不变时不更新 FTS。查询覆盖标题、原始 URL、安全解码 URL、起止时间、无关键词时间范围和冻结 watermark 的 `(matchedVisitTime DESC, pageId DESC)` 游标。真实约 90 万访问数据上常见首页为毫秒到几十毫秒，连续十页无重复或漏项；全量重建 worker、损坏快照拒绝和增量回放均有浏览器回归。
